# 前端无头回归（T-REG 基线）

这些场景来自前端阶段的 Playwright 脚本（原来放在 `/tmp/rl-prof/*.mjs`，不在仓库里）。整理时：
- 每个工作台的点击路径和等待时长都保持原样；
- 去掉了写死的本机路径；
- 加上了统一的失败判定。

它们是 [CODEX_SPEC_RESEARCH.md](../../design/CODEX_SPEC_RESEARCH.md) 中 T-REG 的基线：后端接入以后，前端在 `mock` 模式下这套必须全绿。

## 运行

```bash
npm run dev                       # 另开终端，先起前端（默认 http://127.0.0.1:5173）
node e2e/legacy/run.mjs           # 跑全部 20 个场景
node e2e/legacy/run.mjs au cu     # 只跑指定场景
node e2e/legacy/run.mjs --list    # 列出场景
```

需要能加载 playwright，二选一：
- 在项目里安装：`pnpm add -D playwright`，然后 `pnpm exec playwright install chromium`；
- 或者设环境变量 `PLAYWRIGHT_MODULE=<…/node_modules/playwright/index.mjs>` 指向已有的安装。

其他环境变量：
- `REINLAB_URL`：被测前端的地址。
- `E2E_OUT`：输出目录。默认在系统临时目录，**不会写进仓库**。
- `CHROME_PATH`：浏览器路径。
- `E2E_STRICT_WARN=1`：把控制台 warning 也算作失败。

## 判定

满足下面任一条，场景就失败：
- **步骤失败：** 任何一步找不到元素或超时（单步 10 秒）。原脚本里带 `.catch(() => {})` 的步骤是有意的可选步骤，不计入。
- **页面报错：** 页面抛出未捕获的异常（`pageerror`），或控制台打出 `console.error`。
- **场景断言不满足：** 例如入口转场两段动画录到的帧数过少。

每个场景都把截图存到 `<输出目录>/<场景>/`。整套跑完写一份 `report.json`，内含每个场景的状态、耗时、错误、warning、备注和截图列表。只要有失败，退出码就是 1。

## 已知局限

- 场景按固定等待时长推进，跟原脚本一样。机器很慢时可能偶发超时，复跑单个场景即可确认。
- 前端改了类名或文案，对应场景会失败。这是预期的：先确认改动是有意的，再同步更新场景。
- 只验证流程能走通、不报错，不比对截图像素。视觉上的检查靠人看截图。

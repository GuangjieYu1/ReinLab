# 对外对比记录

每次拿 ReinLab 的功能和外面成熟的产品对比，结论都追加在这里，新的放在最上面。每条写清楚：比的是什么、题目是什么、怎么判的、谁赢在哪、发现了我们哪些问题、后续怎么办。

判断用五条：覆盖、真不真（随机点开链接抽查）、诚实（宣传是否当成事实、负结果有没有写）、有没有用、花了多少。

## 2026-11-05 · 研究台群研 vs ChatGPT 深度研究

**题目**：「以地图为主、人物随时间在地图上行动」的世界观系统，能不能当小说、电影、漫剧和游戏的共同底座？现在做到哪一步，缺口在哪？两边拿到的题目原文完全一样，是给创作台做设计调研用的。

**材料**：
- 群研：档案 `2114263f`，运行 `93f8527c`。
- GPT：`~/Downloads/以地图与时间为主轴的.docx`。

**总的判断：各有胜负。** GPT 查得全，总结也强；群研更细，更会挖条款和价格，但这次的独立核实放过了一条错结论。

| | 群研 | GPT 深度研究 |
|---|---|---|
| 覆盖 | 七个问题都碰到了。国内只找到 Effie、壹写作，就下结论说「国内工具都没有地图」。漏了 OnlyWorlds、articy 和长篇一致性研究 | 更全：国内找到 51码字、创宙工坊、捏宇宙、岸途；还有 OnlyWorlds、articy、ConStory-Bench / FlawedFictions / TimeChara、OSRM / Valhalla、OpenFreeMap |
| 真不真（抽 5 处） | 错 1 处，而且错的两条都标了「已核实」：说 Generative Agents 论文没给成本、两天游戏时间只跑了约 48 分钟。论文原文是「花了数千美元 token、跑了好几天」。chronicle-graph 属实 | 错 1 处：把 51码字写成「商业闭源」，其实它在 GitHub 上开源，MIT 许可。OnlyWorlds 是 MIT 属实，可灵 3.0 Element（2–4 张图、能绑声音）属实，论文成本那句也属实 |

**补充：用户又在 DSH 里单独让 agent 做了一份**，放在 `~/Documents/ChatGPT/游戏攻略/世界观调研/世界观底座调研_2026-11.md`，48KB，88 个链接。三份里它最好：
- 覆盖最广，而且挖到了另两份都漏掉的 **Aeon Timeline**。它是唯一产品级的时间约束工具，违规会标红，能逐条或批量修，正好是我们矛盾检查 UI 可以照抄的样子。
- 还挖到 Watabou、Project Sid、AgentSociety、GenWebNovel、国内地图审图号的规定、Seedance 引起的版权风波。
- Generative Agents 论文成本那句，它直接引了原文，是对的。
- 最后给了一个「90 天垂直切片」：一个城市、3 个人、1 天、10 个事件。
- 抽查 3 处（ConStory 和 FlawedFictions 两篇论文、Aeon 页面）都属实。
- 不足：没找到 OnlyWorlds、articy、51码字。

**群研核实为什么放过错结论（查了审查记录）**：
1. **长页面被截断。** 反驳和核实都去读 ar5iv 上的论文。成本那句在论文靠后的讨论部分，抓回来的文本没到那里。核实的人自己写了「ar5iv 中间章节被截断，无法穷举」，却照样判了通过。
2. **「没找到」也能被盖上「已核实」。** 否定式的结论（某处没有某样东西）要读全了才能下。读不全时应该判「证据不足」，现在的门禁不拦。
3. **两个人不独立。** 反驳和核实用同一个工具读同一个被截断的页面，错法完全一样。「48 分钟」这个错误换算还是反驳的人先提出来的，核实的人照抄了。论文里「1 秒真实 ≈ 1 分钟游戏」是目标速度，实际跑了好几天。
4. 这次运行调了 150 次 web_fetch，这条结论绕过了「先下载原文再读」的路子。研究员按规定不带下载论文的工具。

**为什么群研不如 DSH 单人（翻了两边的会话记录）**：

| | DSH 单人 | 群研 |
|---|---|---|
| 模型 | deepseek-v4.1-flash（经 opencodego） | deepseek-v4-flash（官方），版本低一代 |
| 时长 | 16 分钟 | 20 分钟 |
| 工具调用 | 106 次：web_fetch 66、web_search 19、bash 9 | 569 次：web_fetch 150、web_search 18；提交、审查、发消息、查任务这类协调调用约 280 次，占一半 |
| 读长页面 | 用 bash 跑 curl 把 arXiv 整页拉下来，再用 python 在全文里搜 → 抓到成本那句 | web_fetch 超过约 5 万字就截断，全文存进 `/tmp/dsh-spill…/web_fetch.txt`，提示「用 read 或 grep 去看」。但研究员、反驳、核实都没有 read 和 bash，打不开这个文件。三个人都读到同一个被截断的版本 |
| 谁有 shell | 自己有 | **只有负责人有**（调了 25 次，用来查环境）；真正读资料的人没有，还有 2 次报「unknown tool bash」 |
| 读黑板 | — | research_query 每次返回约 2.3 万字（最多 5 万），上下文被别人的结论占满 |
| 成稿 | 一个脑子从头到尾想，先搭「L0–L7 七层」骨架再填，最后有判断、有 90 天切片 | 按领域分三条路线，各交各的原子结论；没有人负责写贯穿全局的报告，汇总就是把结论分区排好 |

结论：输的不是「多 agent」这个思路，而是四个具体缺陷：
1. **读资料的人工具最少。** 截断以后的全文就在旁边，但打不开。
2. **一半调用花在协调上。**
3. **没有成稿这一步。** 群研擅长逐条较真，不擅长形成观点。
4. **模型低一代。**

**发现的我们的问题**：
- **核实没有真正回到原文。** 核实的人说读了论文全文，却漏了论文里明写成本的那句话，还把它「纠正」成错的。这违背了 MVP-3 的核实规则，要交给 DSH。
- 默认 4 轮就停，还剩一半结论没核实。题目大的时候，追加额度的提示要更早、更显眼。
- 广度不够。漏了几个关键对象（OnlyWorlds、articy、国内带地图的写作工具），说明开局铺的路线不够散。

**对创作台设计的用处**：两边都认同「整条链没人做通」。人物随时间的轨迹、硬性的时空检查、跨作品的设定版本，这三样要自己做。具体结论合进 [prd/16-creative-ux.md](prd/16-creative-ux.md)。

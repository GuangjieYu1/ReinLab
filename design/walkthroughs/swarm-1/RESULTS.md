## 给 DSH 的问题（按严重程度）

- **B1 确认后 2 秒被标成 `partial / answered`，团队却在后台继续跑。** 运行 `2cd454bf`：确认时负责人还在上一回合（重起栈后注入的「继续」），回合一结束就判「任务都交付了」（当时 0 个任务）。「用户已确认计划」还发了两遍（时间线 seq 5806、5807）。页面按契约看到终态就关了事件流，用户看不到真实团队；结束干预也停不住，费用从 ¥0.23 一直涨到 ¥1.08，直到停掉内核。修法：0 个任务 / 0 个交付不能判完成；确认指令要幂等；结束要真的打断已建的成员。
- **B2 同一档案里出现另一个题目的负责人会话。** 同一运行里出现 `ds-cbf98171`，目标是「LLM 智能体长期记忆：召回与遗忘」，在本档案目录下又建了 `res-recall / res-forget / res-audit` 三名队员（快照里一共 7 名成员）。数据库里没有这个题目的群研。请查重起后的「继续」接上了哪个会话、目标从哪来。
- **B3 研究员和路线对不上。** 负责人没在任务里写 `route=` 时，任务的 `routeId` / `parentId` 都是 null，路线卡里一个任务都没有（前端先放进「审查与汇总」）。队员名也随负责人起（`r1-scaling`、`critic`），`label` 都是「研究员」。路线归属应由插件在建任务、建成员时登记，不靠模型写对描述。
- **B4 核实员、反驳员读不到研究员的产出**（两次运行都出现，原话「沙箱把我锁在 team/verifier-01/」）。PRD §5：反驳、核实按审查任务读需要的产物。
- E1 干预事件只推了 `received`，`applied` 没推（暂停那次连 `received` 都没有）；页面要刷新才看到「已执行」。
- E2 队员一直是 `idle`，可它们在干活、费用在涨；结束后负责人还是 `running`；根任务和路线在运行结束后仍是「开放 / 进行中」。
- E3 通信时间线：负责人发给队员的消息，接收方那一条成了 `lead → lead`；运行环境快照、「Background subagent finished」、建队提示词都被记成 `user → lead`（页面显示成「你说的」）。
- E4 队员记录缺契约里的 `at`；负责人的记录里没有正文。开跑后负责人对用户说的话没有出口，同一运行的内核事件里混着各队员的话、又不带成员标识，前端只能显示建队前的回话。
- E5 开跑前快照的 `members` 里没有负责人；根任务用的是 `parentId:"none"`、`routeId:"all"`（契约里是 null）。
- 研究员拿不到 `papers_fetch` / `papers_register`，又读不到页码，于是全队都改用「arXiv 号 + 章节」作依据。这和「证据落到页码」的质量判据冲突，后面做核实时要定下来。

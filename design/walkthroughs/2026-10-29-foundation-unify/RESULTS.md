## U3 阻塞：下载审批批不下来

经过：说「想读提出 Transformer 的那篇原始论文」，25 秒后列出《Attention Is All You Need》✓ → 选定 → 确认 → 3 秒出现审批卡 → 点「批准」→ **9 分钟毫无进展**。

数据（读 run `48302b9d…`）：
- 这个 run 有**两张**审批：`1d89f3d7` 已经 `expired`，`e902bc9a` 还在 `pending`；
- 第一次 `papers_fetch` **几乎立刻**就返回了 `reason: "expired"`（事件 14848），我还没来得及点；
- 之后两次 `papers_fetch` 都返回 `KERNEL_TOOL_HTTP_409`（14854、14860），模型又回头去调 `clarify_question` 问选哪篇；
- 我点的「批准」很可能落在了已经过期的那张卡上，所以没有效果。

**判断：** `01015bd` 新加的「过期」路径有问题：审批刚建好就被判过期（可能是上一个被取消的澄清 run 里还在等待的工具，到期时把 expire 发到了新的审批上，或者计时起点不对）。过期之后同一动作再要审批时返回 409，模型就陷入循环。

**修复（DSH）：**
1. 查清为什么新建的审批会立刻过期：计时是否从「这张卡被创建」开始？被取消的运行里那个还在等的工具，是否会去过期别的审批？
2. 同一个下载动作，任何时候只能有一张有效卡；前端显示的卡必须和那张有效卡是同一个 id。
3. 过期以后再次请求同一动作，应该新建一张卡让用户批，不要返回 409。

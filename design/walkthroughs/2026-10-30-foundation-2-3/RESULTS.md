| T4 / T5 | — 没走到；T5 的课程台页面入口要等 Claude 做 |

## 根因（阻塞）

容器里的插件按**宿主路径**去读运行令牌：

```
ENOENT: no such file or directory, open
'/Users/guangjieyu/.local/state/reinlab/<实例>/kernel/accounts/<账户>/runs/<run>/token'
```

（事件 16957，`clarify_question` 的结果；模型对用户说的「读不到一个 token 文件」也是这个。）容器里没有 `/Users/...` 这个路径。所以在容器模式下，`papers_*`、`clarify_question`、卡片这些**插件工具全部失败**，只有 DSH 自带的 bash / web 能用。DSH 的烟测「completed、调用了 bash」掩盖了这一点。

## 另外两处

1. **自动注入的提醒显示成了「你」说的话**：「这一轮检索到了候选，但用户还没看到可选列表。请调用 clarify_question……」。这是系统给模型的推动，却以用户消息的身份出现在对话里。一来用户会以为是自己说的，二来这算在提示里教模型做事（纲领第 9 条）。要么不显示，要么干脆去掉这个推动。
2. **选定候选后页面回到「想读哪篇？」**：很可能是 `clarify_question` 失败、这一轮结束以后，前端把状态重置了。根因修好后再看。

## 修复（DSH）

1. 令牌（以及插件需要的任何宿主文件）用**容器内路径**传给插件，比如挂载到 `/run/reinlab/token`，并通过环境变量告诉插件；在容器里实际跑一遍 `papers_search` / `papers_fetch` / `card_layer` 确认能用。
2. 自动注入的提醒不以用户身份显示；按第 9 条，考虑直接去掉。
3. 修完在**容器模式**的真实页面上走一遍：说一句 → 候选 → 选定 → 一张入档审批 → 讲解 → 完成。

## 问题（DSH）

1. **工具参数 JSON 坏了导致整轮失败（阻塞）**：讲解卡正文较长时，模型输出的工具参数不是合法 JSON。很可能是输出上限截断了（精读角色每轮输出上限是否还是 1024？）。修法：
   - 把精读角色的输出上限提到 8192（之前定过）；
   - 坏 JSON 当作这一次工具调用失败，返回给模型，不要让整轮直接失败；
   - 已经写好的成果照实保留，结束状态不要写「失败」（写成「完成（部分）」或说明原因）。
2. **又一条以「你」的身份注入的提醒**：「上一次的工具调用参数不是合法 JSON，整轮因此中断。请把那次调用重发一次……」。这一条和之前删掉的两条是同一类，要么不显示，要么去掉。
3. **澄清阶段又能下载了**（工具全开以后），于是提前弹出一张「下载论文全文」审批卡；选定后这张卡被作废，助手面板里留下两张「已过期」的卡，模型还对用户说「确认被取消了，请回一句同意下载」。PRD 上一轮已经定了：澄清阶段不提供下载。全开指的是 bash、网页这类基础工具，**论文入档这一步仍然只在用户选定之后**。
4. **正式读论文时，入档审批卡在研究台页面上不显示**：数据库是 pending（「把这篇论文正式入档」），收件箱里也有，但中间面板和助手面板都没有可点的卡，只能去收件箱批。看起来是前端按「下载论文全文 / papers.fetch」去匹配卡片，标题和能力名一变就认不出来了。这一条涉及 `read-live` 的映射，请 DSH 改；如果需要前端配合，告诉 Claude。
5. 收件箱审批卡的「会发生什么」还是空的。

## 结论

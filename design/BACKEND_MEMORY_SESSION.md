# 后端设计 · 第一篇：记忆与会话

版本 0.1 · 2026-10-18 · 草案，待讨论

## 0. 已经定下的前提

1. **云端服务。** 后端部署在云上，iPad / 浏览器是客户端。
2. **多家模型路由。** 支持 API key、会员计划（ChatGPT / Codex、Copilot 等）、外部 agent 运行时（Claude Code、opencode）、本地或开源模型（如 MiMo），以及多模态（出图、视觉、转录）。每个位置都可以切换模型，以最划算为目标。
3. **能复用就复用。** 执行内核用 OpenScience（Apache-2.0，`../OpenScience`）。其余成熟开源件按第 10 节的清单接入。
4. **第一条打通的链是研究台。** 在那之前，先把所有部分的记忆与会话管理定下来，也就是本文。

一句话原则：**写在本地，升级要批准，跨档案只引用不复制，每个角色只看得到它该看的。**

## 1. 名词

| 名词 | 是什么 | 前端里对应的东西 |
|---|---|---|
| 账户 Account | 一个人。所有东西的所有者 | 登录 |
| 档案 Dossier | **隔离的基本单位**：一门课、一次拍摄、一组例程、一个研究课题、一个数据集、一部作品、一个工作区 | 入口里的档案（X—013…），各台的「文件」 |
| 工作台 Bench | 档案的类型，决定可用的角色、工具和视图 | 七个台 |
| 角色 Role | 一个 agent 的身份：提示词、模型策略、工具授权、可读范围、可写目标、预算 | 课程顾问、独立审查、维护 Agent、设定顾问… |
| 会话 Thread | 一条长期对话，属于某个档案、某个角色 | 学习工作区（每单元一条）、例程助手、写作助手 |
| 运行 Run | 一次有始有终的执行，可能有子运行 | 例程的一次运行、一轮审查、一次排队出图、一轮群研 |
| 委托 Delegation | 一个档案请另一个台做事的合同 | 课程 →（调研）→ 研究台；侦查 → 自动化台 |
| 产物 Artifact | 运行留下的不可变文件，有版本 | 计划书、备课包、侦查报告、出图、转录 |
| 事件 Event | 账本里的一条记录：谁、在哪、做了什么、花了多少、结果 | 动作画布、运行记录、审计导出 |
| 记忆 Memory | 跨运行保留、会影响以后行为的信息 | 见第 3 节 |

## 2. 会话层级：从档案到一次运行

```
账户
└── 档案 Dossier（= OpenScience 的 project：一个工作区目录 + 权限）
    ├── 档案记忆（L2）  study_plan/、world/、spots/ …
    ├── 会话 Thread（= OpenScience 的 session，workspace=project）
    │     角色固定，消息可压缩；每条会话有自己的 L1 记忆
    └── 运行 Run（= OpenScience 的 run receipt）
          └── 子运行（= child session，workspace=isolated）
                委托出去的工作、群研里的子 Agent、独立审查
```

**规则：**

- 会话不跨档案。同一个人问两门课，是两条会话。
- 子运行默认是**隔离工作区**（OpenScience 的 `isolated`）。它只拿得到父运行显式交给它的文件和记忆片段。
- 运行结束必须留下：事件（账本）、产物（如有）、结论摘要（写回父会话的 L1）。

### 2.1 各工作台怎么映射

| 工作台 | 档案 | 长期会话（角色） | 典型运行 | 子运行 / 委托 |
|---|---|---|---|---|
| 研究 RSCH | 一个研究课题 | 精读助手、群研指挥、自研循环 | 精读一篇论文；一轮群研；自研的一次迭代 | 群研的 32 个子 Agent；精读里的复现 |
| 课程 CURR | 一门课（`study_plan/`） | 课程顾问；每个单元一条学习工作区 | 一段备课；一轮独立审查；一次考核评分 | 调研 → 研究台；侦查适配 → 自动化台；独立审查与复核是隔离子运行 |
| 工程 ENGR | 一个代码工作区 | 需求助手、开发助手、测试助手 | 一次补全校验；一次测试运行 | 修复 diff 的试跑（沙盒） |
| 创作 CRTV | 一部作品 | 设定顾问、写作助手、分镜导演 | 一次矛盾检查；一章续写；一次出片 | 出图 → 自动化台节点图 |
| 自动化 AUTO | 一组例程或节点图 | 例程助手、节点助手、维护 Agent | 例程的一次运行；一次排队出图；一次沙盒重放 | 例程调用 @工具（节点图、其他台） |
| 探索 EXPL | 一份拍照计划 | 计划助手、现场助手、回顾助手 | 生成计划书；现场重排；整理观察 | 全网景点调研 → 研究台；照片 → 创作台；归位 → 自动化 |
| 数据 DATA | 一个数据集 | DataAgent | 一次派生；一次出图 | 图表风格 → 创作台（可选） |

## 3. 记忆分层

| 层 | 名字 | 范围 | 谁写 | 谁读 | 寿命 | 存在哪 |
|---|---|---|---|---|---|---|
| L0 | 上下文 | 一次运行 | 运行时 | 本运行 | 运行结束即弃 | 模型上下文；OpenScience 负责压缩 |
| L1 | 会话记忆 | 一条会话 | 本会话的角色 | 本会话 | 跟会话走 | 会话摘要、待办、钉住的事实 |
| L2 | 档案记忆 | 一个档案 | 档案内角色，按「可写目标」 | 档案内角色，按「可读范围」 | 跟档案走，有版本 | 档案工作区里的文件 + 结构化事实表 |
| L3 | 个人记忆 | 整个账户 | **只能经「升级」写入** | 所有台，按角色过滤 | 长期，可撤销 | 侧写、偏好、器材、约束、经验 |
| L4 | 知识库 | 整个账户（未来可共享） | 运行的产物登记 | 所有台，**按引用** | 长期，不可变版本 | 论文、地点、数据集、模型、引文 |

另有一类**规程记忆**：怎么做事，比如技能（skills）、例程、模板、「下次」的经验。它本质上是 L3 / L4 里可执行的那部分，存成技能包或例程版本，同样走升级流程。

### 3.1 每层放什么（按台举例）

- **L1 会话**：学习工作区 U1 里「你三次问举例子」；例程助手里「这条例程你改过两次触发」。
- **L2 档案**：
  - 课程：`goal.md`、Preflight Plan、调研结果、侦查报告、蓝图、备课包、rubric v1.2（锁定）、作答记录。
  - 创作：世界观实体与关系、年表、已定稿章节。
  - 探索：机位、服饰、天气快照、现场记录。
  - 自动化：例程版本、运行记录、故障与修复。
  - 研究：findings、实验记录、frontier 曲线。
- **L3 个人**：
  - 学习者侧写、能力掌握档案（来自课程「收尾」）。
  - 审美偏好（常选的配色与焦段）、常用器材、预算习惯、时间约束。
  - 写作风格、工程习惯。
- **L4 知识**：
  - 读过的论文（含精读批注）、核实过的资源（含「能不能打开 · 能不能读」的结论与日期）。
  - 去过、调研过的地点与机位、数据集、模型文件。

## 4. 同步与隔离的规则

**R1 写在本地。** 运行只能写到它所在的会话（L1）或档案（L2），并且只能写到角色的「可写目标」里。比如独立审查只能写 `review.md`。

**R2 升级要批准。** L1 / L2 的内容要进入 L3 / L4，必须是一条「升级事件」：
- 来源：哪个档案、哪个运行、哪几条证据。
- 内容：要写入的条目。
- 目标层。
- 你的批准。

已有的例子：
- 课程的「正式收尾」→ 学习者侧写与能力档案（L3）。
- 探索的「下次」→ 经验（规程记忆）。
- 侦查结论 → 资源可用性（L4）。
- 精读完成 → 论文与批注（L4）。

**R3 跨档案只引用。** 一个档案要用另一个档案或知识库里的东西，存的是「ID + 版本」，读的时候检查权限，不复制内容。原内容更新时，引用方会看到「有新版本」，而不是被静默改掉。
- 例：课程引用研究台的调研结论；探索引用知识库里的机位。

**R4 角色视图。** 每个角色有一份「可读范围」清单。记忆服务按清单过滤，运行时只拿得到过滤后的内容。
- 独立审查：能读备课包和资源原文，**不能读**备课对话。
- 复核：能读题目、作答、锁定版 rubric 和材料，不能读讲师对话。
- 维护 Agent：能读失败运行的输入与日志，能改例程草稿，**不能**批准上线。
- 学习工作区 U1：能读 U1 的单元、资源、定位；读不到 U2 的会话。

**R5 只追加，不覆盖。** 事实有版本链。新版本「取代」旧版本，旧版本仍可查。
- 锁定过的东西（rubric、已上线的例程版本、已提交的考核）不能被静默修改，只能发新版本，并且新版本不影响已发生的评分或运行。

**R6 可以撤销。** 你可以撤销一条 L3 / L4 记忆：
- 依赖它的产物标为「依据已撤销」，交给你决定要不要重做。
- 撤销本身也是一条事件。

**R7 门禁写在账本上，不写在界面上。** 「蓝图未批准不能创建单元」「U1 未通过不能推进 U2」，由控制面根据账本状态判断。页面、聊天工具、直接接口走的是同一个判断，换入口也绕不过去。

## 5. 角色与能力隔离

```
角色 = 提示词 + 模型策略 + 工具授权（按只读 / 写入 / 危险）+ 可读范围 + 可写目标 + 预算
```

- 控制面在每次运行开始时，签发一张**运行令牌**：档案、角色、工具白名单、记忆范围、预算上限、有效期。
- 执行内核（OpenScience）的工具层和记忆服务都只认这张令牌。
- **危险动作**（删除档案、清空表、对外发布）不进任何角色的白名单，只能由你在界面上点。
- **写入动作**默认「询问」。你可以在例程里改成「允许」，但改动本身要批准（自动化台的权限表就是这个）。
- **同一个模型扮演不同角色时，上下文完全不共享。** 独立审查和备课即使用同一个模型，也是两次独立运行，各拿各的令牌。

## 6. 委托合同

```
Delegation {
  from: { dossier, run, role }        // 谁请的
  to:   { bench, role }               // 请谁做
  input: [ref…]                       // 只给引用，不给整个档案
  scope: { read: [...], write: [...] }
  budget: { money, tokens, minutes }  // 从发起方预算里划出
  expect: schema                      // 期望的产出格式，例如 research_findings@1
  gate:  'none' | 'approve-before' | 'approve-after'
}
```

- 被委托方在**自己的台**里开一个档案（或复用已有档案），产出登记为产物，结果以引用的方式回到发起方。
- 双方账本都各记一条，审计可以跨台串起来。
- **负结果也是结果。** 「没找到」要按 schema 交回，不能当作失败吞掉。
- 发起方只批准了这一段，就只做这一段（课程的三阶段 Plan 就是这个语义）。

## 7. 事件账本

```
Event { id, at, account, dossier, thread?, run?, role, kind, action, input_ref?, output_ref?, cost?, risk, decision?, supersedes? }
```

- 只追加。复用 OpenScience 的 run receipt：同一个请求 ID 返回同一个运行，不会重复执行外部副作用。
- 以下都是账本的**视图**，不另存状态：
  - 门禁状态
  - 课程的动作画布
  - 自动化的 14 天运行矩阵
  - 维护的四道工序
  - 数据线程的来源链
- 审计导出：按时间重放事件，复建执行顺序与费用汇总（课程台的「导出审计」）。

## 8. 模型路由与会员计划

**按「位置」配模型，而不是全局一个模型。** 位置举例：
- 顾问对话、长推理、便宜的批量摘要
- 视觉理解、出图、转录 / OCR、嵌入
- 独立审查（建议和被审查方用不同模型）

**凭据分四类：**

| 类型 | 例子 | 计费方式 | 备注 |
|---|---|---|---|
| API key | DeepSeek、OpenAI、Anthropic、OpenRouter… | 按 token 记账（¥） | 默认方式；OpenScience 已支持 models.dev 目录 |
| 会员计划 OAuth | ChatGPT / Codex、Copilot | 记「额度消耗」，不记 ¥ | OpenScience 已支持 Codex OAuth 与 Copilot |
| 外部 agent 运行时 | Claude Code、opencode | 作为「执行器」跑一次子运行，记时长与额度 | 不当作模型接口，而是当作一个会自己调工具的子 agent |
| 自托管 / 开源模型 | MiMo 等开放权重模型、本地或 GPU 机部署 | 记算力时长 | 适合批量、隐私敏感的任务 |

**每个位置可以切换模型。** 账本记下这次用的是哪一类凭据，费用视图把「¥」「额度」「算力」分开显示。

> ⚠️ **会员计划的条款要逐家核对。** 个人订阅一般只授权本人使用。按多人设计（第 12 节），会员计划只能由每个用户本人登录、只用于他自己的运行，不做共享或池化。条款不允许在第三方服务里使用的那一家，就只提供 API 方式。

## 9. 云端拓扑（草图）

```
iPad / 浏览器
   │  HTTPS + SSE
网关（登录、租户、限流）
   │
控制面（TypeScript）
   ├─ 档案、角色、令牌、门禁
   ├─ 账本（Postgres，只追加）
   ├─ 记忆服务（Postgres + pgvector；L1–L4 + 作用域过滤）
   ├─ 委托与编排（长流程：持久化工作流引擎）
   └─ 路由策略（位置 → 模型 / 凭据）
   │
执行面（每个账户一个隔离容器）
   ├─ OpenScience 运行时（openscience serve，headless）
   │     会话、工具、技能、MCP、计算任务；档案 = project 目录
   └─ 档案工作区卷 + 对象存储（产物）
   │
专用服务（按需）
   ├─ ComfyUI（GPU，自动化台节点图）
   ├─ Data Formulator（数据台）
   ├─ OpenMAIC（课堂）
   └─ 转录 / OCR / 文档解析
```

**为什么每个账户一个执行容器：** OpenScience 设计上是本机单用户。它自己说明了「project 不构成租户隔离」，需要网关加执行边界。云端用容器把它包起来，这样不用改它的核心。

## 11. 研究台怎么落在这上面（预告，下一篇展开）

- **精读**：一个档案 = 一篇论文。一条精读会话，复现走子运行。批注与复现结果在你确认后升级进知识库（L4）。
- **群研**：指挥会话 + N 个隔离子运行。
  - 需要给 OpenScience 加一层**可观察的 Agent 间通信**：消息总线写进账本，前端的「通信是主角」直接读它。
  - 每个子 Agent 只拿到指挥分配给它的那一份记忆。
- **自研**：一个长运行，每次迭代是子运行。
  - 预算门禁写在账本上：超出就停，等你批准。
  - frontier 曲线是账本的视图。

## 12. 已决定（2026-10-18）

1. **多人设计。** 从第一天按多租户做。
2. **L3 / L4 升级全部手动批准。** 每次上线（登录或回到应用）时，自动弹出「待你批准的更新」。
3. **长流程编排用 Hatchet。** 和账本、记忆共用一个 Postgres。
4. **OpenScience 作为上游依赖。** 不 fork，只通过 SDK、agent 定义、插件、MCP 扩展，中间隔一层翻译层（第 14 节）。

### 12.1 多人设计带来的变化

- **租户隔离：**
  - 每个账户一个执行容器，档案工作区卷按账户分开。
  - 控制面数据库用行级安全（RLS），所有查询带账户 ID。
  - 对象存储按账户分前缀，签名 URL 限时。
- **凭据：**
  - 每个用户的 API key / OAuth 令牌加密存放（KMS 托管密钥），只注入他自己的执行容器。
  - 日志与账本里只记凭据类型和指纹，不记明文。OpenScience 自带的凭据脱敏照常保留。
- **会员计划：**
  - 只能由用户本人登录、只用于他自己的运行，**不做任何形式的共享或池化**。
  - 没有会员的用户走 API 计费，或平台托管的按量计费。
  - 每家条款在接入前逐一核对，条款不允许的那家就只提供 API 方式。
- **计费与配额：** 每个账户有总预算。档案、委托、运行逐级划拨，超出即停在门禁上等用户决定（和前端的「预算门禁」一致）。
- **共享（以后）：** L4 知识库将来可以在用户之间共享，比如公开的机位库、课程模板。共享的是**新的、只读的副本加出处**，不会打开对方的档案。

## 13. 「上线时待批准」收件箱

所有 L1 / L2 → L3 / L4 的升级请求，以及其他需要你决定、但不阻塞当前运行的事项，都进同一个收件箱。

```
PendingPromotion {
  id, account, created_at
  from: { bench, dossier, run, role }      // 谁提议的
  target: 'L3.profile' | 'L3.preference' | 'L3.procedure' | 'L4.knowledge'
  items: [{ key, value, evidence: [eventRef…], supersedes? }]
  reason: string                            // 为什么值得记住
  expires_at?                               // 过期未处理就作废，不会默认通过
}
```

- **什么时候弹：** 登录、从后台回到前台，或者距上次处理超过一段时间时。不是每来一条就打扰你。
- **怎么展示：** 按工作台分组。每条显示「要记住什么 · 依据（点开回到原对话或作答）· 会影响哪些以后的行为」。
- **可以做的操作：**
  - 批准
  - 改一下再批准
  - 驳回
  - 只留在本档案（不升级，但 L2 里保留）
- **约束：**
  - 不批准就不生效。
  - 收件箱处理之前，相关的 L3 / L4 读取用的是旧版本。
  - 过期作废，不会默认通过。
- **例子：**
  - 课程收尾的学习者侧写
  - 探索「下次」的经验
  - 侦查得出的资源可用性
  - 精读后的论文批注

**前端实现（2026-10-24，Claude）：** `src/components/inbox/`。
- `InboxPanel`：档案夹式弹层。左侧按工作台分组，中间依次是「要记住什么 · 将替换的旧条目 · 依据（可展开原文、回到原对话）· 为什么 · 会影响什么」，底部四个动作。键盘：↑↓、A / E / L / R、Esc。待确认动作只能「批准这一次 / 驳回」；结果未知的动作不能再次操作。
- `InboxHost`：负责弹出时机：登录后到达终端时一次；离开超过 30 分钟、回到前台时再一次。导航条上有带数字的入口。打开时会卸下背后的 3D 档案场，释放 GPU。
- **数据接口：** `inboxTypes.ts` 里的 `InboxAdapter`，字段与后端 contracts 对齐。示例实现在 `mockInbox.ts`；**live 版由 Codex 按同一接口实现**，界面不改。
- **预览与回归：** `?preview=inbox` 单独打开；T-REG 场景 `inbox`。
  - 维护 Agent 总结出的例程写法规律

## 14. 翻译层（ReinLab ⇄ OpenScience）

**为什么要有：** OpenScience 有它自己的概念与协议，我们的前端有另一套。翻译层是唯一同时认识两边的地方。OpenScience 升级时只改这一层，七个台不受影响。我们的风格（中文、角色语气、卡片化输出）也在这一层统一生成，不依赖模型自觉。

### 14.1 下行：ReinLab 的概念 → OpenScience

| ReinLab | OpenScience | 做法 |
|---|---|---|
| 档案 | project（工作区目录） | 每个档案一个 project 目录，挂在账户容器的卷上 |
| 角色 | agent 定义（`.openscience/agent/*.md`） | 由角色表**生成** agent 文件：frontmatter 写模型、步数上限、`permission` 规则、可派发的子 agent、技能；正文是角色提示词 |
| 运行令牌（工具白名单、风险级别） | `permission` 规则 + 插件钩子 | 白名单生成成 permission 规则；插件钩子在调用前再校验一次令牌，双保险 |
| 记忆范围（L1–L4） | 运行开始时注入的上下文 + 记忆工具 | 记忆服务按角色过滤后，以「项目说明」形式注入；运行中按需检索，走我们提供的 `memory_read` / `memory_propose` 工具（插件提供） |
| 委托 | 子会话 / Task 派发；跨台时由控制面调用对方台 | 同台委托用 OpenScience 的子 agent；跨台委托由控制面开对方台的运行，不让 agent 直接跨台 |
| 位置 → 模型 | agent 的 `model`、provider 配置 | 路由策略生成到每个角色的 agent 定义里；用户在某个位置换模型，等于重新生成那个角色的定义 |
| 门禁、审批 | permission 的「询问」+ 我们的门禁服务 | 风险动作在 OpenScience 里是「询问」；询问被翻译层拦下，转成我们的审批卡，用户在 ReinLab 前端决定后回填 |

### 14.2 上行：OpenScience 的事件 → ReinLab 的账本与界面

| OpenScience 吐出的 | 翻译成 | 前端看到的 |
|---|---|---|
| 运行事件流（`RuntimeEvent`，有 sequence） | 账本事件（去重键 = runID + sequence） | 动作画布、运行记录、审计 |
| 模型的文本输出 | 角色消息 | 助手气泡 |
| 工具生命周期（开始 / 结束 / 失败 / 用量） | 工具事件，带风险级别与费用 | 折叠成一行的工具调用 |
| 权限请求、提问（live decision） | 待审批事件 | 审批卡、回答卡 |
| 产物、文件写入 | 产物登记（版本、哈希） | 计划书、备课包、报告 |
| 用量与费用 | 计费事件（¥ / 额度 / 算力分开） | 预算条、费用汇总 |

断线重连照 OpenScience 的约定：先取快照和游标，再续读事件。有缺口就用快照恢复，**永远不重发 prompt**。

### 14.3 风格：怎么保证输出是「我们的样子」

靠模型自觉不可靠，所以分三层保证：

1. **提示词层：** 每个角色的 agent 定义里写明：语言（中文）、语气、篇幅、禁止事项（例如审查角色不得放宽标准）。这些由角色表统一生成，不手写在各处。
2. **结构层（最重要）：** 凡是前端要渲染成卡片的东西，都不让模型输出自由文本再去解析，而是让它**调用一个结构化工具**，由插件提供：
   - `card.answer`（回答卡选项）
   - `card.approval`（审批）
   - `plan.propose`（下一阶段 Plan）
   - `finding.record`（调研结论，含负结果）
   - `memory.propose`（升级请求）
   - `review.verdict`（审查判定）
   - ……

   工具参数有 schema，翻译层直接映射成前端组件。模型说得再啰嗦，卡片也是规整的。
3. **呈现层：** 文本里的术语、单位、引用格式由翻译层统一，例如「出处 · R4 p.6」、「¥2.4」、时间格式。前端只负责莱茵风格的视觉。

### 14.4 放在哪里

翻译层是控制面里的一个独立模块（`bridge/openscience/`），对内只暴露 ReinLab 的接口。规则：
- 七个台和前端都**不直接**依赖 OpenScience 的 SDK 类型。
- OpenScience 的版本在这里锁定，配一套契约测试：用 OpenScience 自带的本地 fixture provider 跑一遍，确认事件映射没变，再升级。

# 探索台 · 用户体验结论（用户与 Claude 头脑风暴，2026-10-31）

本文件只记"用户要什么样的体验"。技术方案、数据源、分期由用户和 Codex 另行 grill 后写进 PRD。现有前端（`src/components/workbenches/explore/`，计划 / 机位 / 现场 / 回顾四个面）的视觉和交互是起点，不推翻。

## 1. 谁在用、怎么用

- 四种拍法都有：带模特外拍人像、一个人拍风光、旅行顺路拍、街拍扫街。
- 做计划的时机也都有：提前几天在电脑前慢慢排，前一晚按预报调整，到现场再改。
- 地域：国内、国外都要支持。

## 2. 一份计划的骨架（四种拍法共用）

- 一条路线 + 沿途若干"停留点"。停留点有三种：**固定机位**（人像、风光）、**一片街区**（扫街，不定具体站位）、**顺路点**（旅行行程里的拍摄机会）。
- 按拍法显隐内容：有模特才出现引导词、服饰、姿势；风光突出光线、云量、山影、日出日落方位；旅行以行程为主，拍摄穿插其中。
- 计划属于一份探索档案（地基第 4 项），可以随时回来继续改。

## 3. 边聊边排（第一版核心）

- 由对话驱动，像和摄影搭档商量：助手先问清地点、日期、拍法、想要的感觉，再逐步提出机位。
- **候选只有一份**：助手提出的机位同时出现在地图上（待定样式）和对话里（候选卡），每个候选带一句理由和最佳时段。在地图上或对话里点"留下 / 不要"都行，两边同步。
- 用户也可以在地图上点一个位置，问"这里几点拍最好"，助手按真实太阳、地形、天气回答，可以加进计划。
- 已确认的机位按时间连成步行路线；时间线显示当天真实的光线带、太阳高度和逐时天气。

## 4. 参考图（第一版就要）

- 用户会贴参考图，表示"我想拍这种感觉"。这件事很重要。
- 助手读图，把光线方向、时段、色调、焦段、构图、姿势整理成一张"想要的感觉"卡，钉在计划上；挑机位、定时间、写引导词都参照它。
- 需要一个能看图的模型（DeepSeek 目前看不了图）。

## 5. 参考图不生成，用真实的

- 不做"模拟生成"的样片和服饰图。助手上网找真实的同机位照片、真实的穿搭参考，**注明出处**。
- 现有前端里的"模拟生成"占位改成真实参考图加出处。

## 6. 账户级资料：模特和器材

- **模特**：常合作的人可以存下来（称呼、身高、风格、经验、衣橱要点、上次合作的经验）。下次排计划直接选人，助手记得 ta 的特点。只存用户填写或确认过的内容，可以随时修改和删除。
- **器材**：存机身和镜头。每个机位只推荐用户手上有的焦段，装备清单自动生成。
- 这两样跨计划共用，不属于某一份档案。

## 7. 天气变化：助手主动提醒

- 计划确定后，后台定时拉取预报（只拉数据，不调模型）。
- 变化大到影响机位时（下雨、云量突变、日落被遮），助手出一份调整方案进收件箱：前后对照，点"应用"才改计划，不点就不动。

## 8. 计划书：两版都要

- **精简版**：一页纸，路线小图 + 时间表 + 每个机位一行要点，现场不用翻页。
- **详细版**：一页总览 + 每个机位一页（构图、焦段、光线、引导词、服饰、真实参考图、规定、雨天备选）。
- 都能打印（A4），在手机上打开时自动改成单栏，排版同样好看。

## 9. 现场（iPad 横屏，第二版）

一眼要看到：
- 现在 / 下一个机位 + 倒计时（还剩多久该走、走过去要几分钟）
- 此刻的光：太阳位置、影子方向、离金色时刻还有多久
- 引导词：大字，可以直接念给模特听
- "拍到了" + 一句话记录（顺手记现场情况，回顾时用）

"情况变了"由助手重排，先给前后对照，点"应用"才改（现有前端已有这个交互）。

## 10. 回顾（第二版之后）

- 照片主要来自相机卡导出的原片 / JPG，多半没有 GPS。按拍摄时间对上计划里的机位时段和现场"拍到了"的时间来落位；导入时提供一步"对时"，校正相机时钟的偏差。
- 其余沿用现有前端：精选、按主题整理现场碎片、游记草稿；"下次"的经验写回计划；交给其他台等台间委托做好再接。

## 11. 第一版做到哪里算"能用了"

**计划 + 计划书**：在真实地点、真实日期，边聊边排出一份计划（含参考图理解、真实参考图、模特和器材），在真实地图和时间线上看得到，能打印精简版和详细版，手机上打开也好看。现场和回顾放到下一版。天气主动提醒放第一版还是下一版，和 Codex 一起定（Claude 倾向放第一版：只拉数据，不调模型，成本低，而且计划是提前几天排的）。

# 17 · 群研返工 · 给 DSH 的开场

日期：2026-11-05。分支：`codex/swarm-4`，从 main 拉出。

起因：同一个调研题目，我们比了三方——群研、ChatGPT 深度研究、DSH 单人（不组队，直接让一个 agent 查）。群研三方里最差，DSH 单人最好。对比、抽查和原因分析见 [BENCHMARKS.md](../BENCHMARKS.md) 2026-11-05 一条。运行是 `93f8527c`（档案 `2114263f`），用的是用户的账户。

一句话：**输的不是多 agent 这个思路，而是读资料的人没工具、一半调用耗在协调上、没有成稿、模型低一代。** 另外，核实放过了一条错结论。

## 用户已定（2026-11-05）

1. **队员的工具完全开放。** 研究员、反驳、核实、负责人，和 DSH 单人默认的工具一样：bash、read、grep、write 等都给，下载和登记论文的工具也给。这推翻了 11-03「研究员不带 papers_fetch / papers_register」的决定。理由有两个：DSH 单人正是靠 `curl` 加 python 读完整篇论文，才抓到群研漏掉的那句话；群研以前提过「把查到的开源项目在本地部署试一下」，也是因为没有 shell 才作罢（结论原文：「我们这边跑不了 AI Town……本会话没有 shell/exec 工具」）。
2. **黑板只返回摘要和增量。**
3. **加「成稿」这一步。**
4. **群研的模型换成 deepseek-v4.1-flash。**

## 要做的

1. **工具开放**
   - 所有队员拿到和 DSH 单人一样的工具。
   - `web_fetch` 截断后会把全文存进 spill 文件，队员要能用 read 或 grep 打开。
   - 要能在账户容器里装依赖、跑开源项目试用。
   - 写黑板的入口仍然只有 `research_submit` 一个，其他工具不能绕过它直接写黑板。
   - 底线照旧：宿主的 key 不进队员的环境变量、命令行参数和日志。队员自己要用 LLM 时，走模型网关的临时 key，费用照样记账。
2. **核实门禁补一条**
   - 否定式结论（「X 里没有 Y」）只有在核实者确认读全了原文时，才能判「已核实」。
   - 核实者自己写了「截断 / 读不全」，就只能判「证据不足」。
   - 核实最好换一种读法或换一个来源，比如原文 PDF、另一个版本、用 bash 在全文里搜，不要和反驳读同一份截断文本。
   - 这是 PRD §5「回到原始出处去核」的落实，不是新规则。
3. **黑板减负**
   - `research_query` 默认只返回结论摘要（id、状态、一句话），再加上自上次读取以来的增量。要看全文时按 id 取。
   - 这次每次读黑板平均返回约 2.3 万字，最多 5 万。
4. **成稿**
   - 运行结束前（`final` / `partial` 都算），由负责人写一份贯穿全局的报告：先搭框架，再给判断、建议，以及我们能照搬什么、要自己做什么、风险在哪。
   - 引用只能指向黑板上的结论和证据 id；没核实的要在文中标出来。
   - 放进 `report` 的新字段 `narrative`（markdown）。契约 13 §2 的 report 加这一个字段，其余不变。前端由 Claude 接，在汇总面最上方显示。
5. **模型**
   - 群研各角色默认用 `deepseek-v4.1-flash`。先确认官方 API 有没有这个型号；没有的话，回来说要接哪家。用户的 DSH 是经 opencodego 用的。
   - 每个角色的模型做成可配置（先用配置项，设置页以后由 Claude 做）。`usage_record` 记上真实型号和单价。

## 验收（Claude 在真实页面上做）

用同一个题目重跑一次，题目原文在 BENCHMARKS 里，预计 ¥4–8。和三方对比，至少要做到：
- Generative Agents 论文成本那句核对正确；
- 漏掉的对象里至少找回一半（OnlyWorlds、articy、Aeon Timeline、51码字）；
- 汇总面有一份能直接读的报告。

结果追加到 BENCHMARKS 和 COST_LEDGER。

## 规矩照旧

- 不新增审计类测试；
- 费用只记不拦，按峰值费率估算；
- 提示词只写底线，不教模型做事；
- 每批一个提交，用 `--no-gpg-sign`；
- 交付单写清楚：工具清单、新的门禁怎么在审查记录里看到、`narrative` 的样例、换了什么模型和单价。

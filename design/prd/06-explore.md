## 1. 第一版目标与范围

在真实地点、真实日期，用户与摄影搭档式助手边聊边设计旅拍计划。中间地图是助手可以实时操作的规划画布，右侧对话呈现实际操作和沟通；用户看到候选、路线、草图和笔记逐步形成，最终确认计划，打印或保存两种计划书。

- 支持人像、风光、旅行顺路拍、街拍，按需要组合；有人像需求才出现模特相关内容。
- 第一版包含：真实地图及卫星切换、地点搜索与步行路线、参考图理解及真实参考图搜索、太阳与山影估算、天气与主动提醒、账户级模特和器材、计划持久化、网页/打印/PDF 计划书。
- 国内、国外地点均支持；首先在用户本机网络跑通，不承诺本轮完成国内无代理部署。
- 现场模式、回顾、相机对时、街景、2.5D 白模及建筑/树木遮挡放后续；不扩展驾车或公交路线。
- 保留现有四个工作面的视觉与交互起点；未接通的后续功能不以示例内容冒充真实结果。

### 2.2 服务配置与地图公开 key

用户明确允许**地图专用公开访问 key**进入浏览器，前提是服务商端限制 Allowed HTTP origins。为实际本地页面 origin 和后续正式 origin 分别配置，不使用无限制通配；只用于地图公开资源，不把管理 key 或其他服务凭据交给前端。页面请求 MapTiler 官方服务，不用后端转发来隐藏该公开 key。

其他密钥保持原规则：只从 `~/.config/reinlab/local.env` 在服务端进程内存读取，不进入环境变量、argv、日志、聊天或浏览器。高德 Web 服务、ORS、OpenTopography 和 DeepSeek 的凭据不享受地图公开 key 例外。

实施前需要可用的 MapTiler、地图/路线、高程服务配置；免费额度、账户套餐与目标地区数据覆盖以实际配置为准。不在本文设预算金额、不购买订阅、不启动调用。Open-Meteo 非商业免费服务与商业服务按实际使用性质选择。

MapTiler 图层显示官方要求的署名；卫星影像是历史影像，不称实时、不承诺所有地方同样清晰。第一版计划书默认使用莱茵矢量地图静态图，避免依赖卫星影像导出授权；若另加卫星导出，须符合所用套餐的打印/导出条件。公开 key 的来源限制也应覆盖实际生成页面，不为 PDF 导出关闭限制。

## 3. 计划对象、状态与确认

### 3.1 经典协作流程

**澄清旅拍需求 → 设计本次工作的方案 → 用户批准 → 助手执行旅拍计划编排 → 用户确认旅拍计划 → 待执行。**

“执行编排工作”与“实际出行”不同：批准助手开展设计，不自动代表接受它提出的每个机位。澄清与方案沿用地基原生计划/提问机制，不要求模型固定提问顺序、固定报告形式或固定调用次数。

第一版每份探索档案维护一份当前计划，保存修订与成果快照。计划有草拟、待执行、结束、取消的业务状态；档案归档沿用档案生命周期，不混成模型运行状态。明确说“就按这个安排”或页面确认整份计划才进入待执行并启用天气检查；点某个候选“留下”只确认该点。

确认既支持逐点，也支持一组/整份，以整份为主。明确要求的修改直接执行，不重复审批。修改待执行计划后仍保持待执行，以最新计划检查天气；建议尚未获批时不改变生效计划。

### 3.2 数据语义

计划保存目的地、地点时区、日期/拍摄时段、拍法与感觉、模特/器材引用及快照、停留点、步行路线、画布笔记、参考资料和当前修订。支持行程日期范围，逐日呈现时间线；每段时间明确所属当地日期，不能只存“当天分钟数”。

停留点类型与拍法分开：

| 停留点类型 | 几何与用途 |
|---|---|
| 固定机位 | 明确点位，可带拍摄朝向、视角和主体位置 |
| 一片街区 | 区域/范围，可带入口、出口和探索建议；不能把区域中心伪装为已确认站位 |
| 顺路点 | 行程中的拍摄机会，保存位置与预计停留窗口 |

每个停留点有稳定 ID、候选/已确认两种状态，以及名称、来源、理由、预计时间、建议光线和相关内容。参考图、服饰、构图、引导词按需出现，未知字段不编造。拒绝候选后从有效候选中移除，不把“不要”设成第三种有效状态。

地图、聊天候选卡、时间线读取同一对象。已确认停留点按时间计算真实步行路径与预计时间；不将直线连点算成步行路线。路径不可得时明确未取得；到达时间不足以赶上拍摄窗口时说明冲突，交由用户/助手调整。器材建议使用用户确认拥有的机身和镜头；未填器材先澄清，不自行假定拥有。

## 4. 地图与 AI 实时规划画布

### 4.1 地图表达

矢量/卫星按钮切换底图，保留视野、停留点、路线和草图。矢量图呈现道路、水系、建筑轮廓、地名、等高线，按缩放控制密度；建筑是地图轮廓，不是第一版遮挡模型。地图配色、文字与标注遵循莱茵语言，由 Claude 完成具体视觉契约。

业务位置统一为 WGS84 经纬度；瓦片投影由引擎处理。保留供应商原始坐标与坐标系，高德 GCJ-02 在边界适配中转换，反向请求高德时再转换；点、路线全体顶点和区域均按同一语义处理，避免重复偏移。太阳、天气、高程不接收未经转换的 GCJ-02。实现核对国内真实地标和路线对齐；转换近似误差不宣称测绘精度。

### 4.2 助手能操作什么

- 读取视野、选中位置、画布对象及关联停留点；查询指定范围内可用地图要素。
- 自主移动、放大、缩小、适配范围、切换底图。
- 添加/修改/删除标注、箭头、折线/自由线、圈选区域、文字笔记，关联参考图、地点或停留点。
- 创建和调整候选；显示真实路线；展示太阳方向、拍摄朝向及光线时间。

助手决定何时用这些工具，不规定“先缩放再画圈再查天气”。不通过模拟鼠标动作实现产品内部控制，不要求生成任意前端代码。

### 4.3 实时、生效与持久化

DSH 工具产生结构化业务动作，经控制面记录并推送给页面；每次有效操作及时呈现，右侧同步简短事实记录，如“圈出白川附近街区”“补充夕阳方向”，不能等整段回答结束再一次性加载。显示实际动作及必要解释，不暴露或伪造模型内部思维过程。

地图草图、正式停留点与导航路线明确区分。草图线不冒充可通行路径；地图笔记不是自动确认的账户资料。标注以地理坐标保存，缩放和平移后仍落在原处；箭头/字体屏幕尺寸由前端渲染管理。刷新或重新打开能恢复有效画布与计划，不重放过时镜头动作。

用户能移除/修改笔记并撤回最近的画布改动；删除正式停留点仍走正式计划语义。用户手动操作地图时可暂停跟随助手视野，再恢复跟随；助手继续产出内容，不持续抢回镜头。切换底图不清空草图。页面未打开时仍保存画布状态；后台天气任务不移动用户当前视野。

复用现有事件和操作记录，记录稳定对象 ID、修订、来源、动作与结果；页面和工具共用业务动作。只在成功后声明已生效，相关用户修改在下一次模型调用中可见。具体事件与前端状态结构由 Claude 契约定义。

## 5. 太阳、地形与天气

### 5.1 山体遮挡

SunCalc 按真实地点与时间计算太阳高度、方位和日出日落；统一为真北 0°、顺时针方位，与地图和拍摄方向一致。金色/蓝调带采用明确且前后一致的太阳高度定义，分别展示天文时段与地形见光时段。

获取机位周围 Copernicus GLO-30 高程栅格，而不是只查机位海拔。以机位高程加观察高度为起点，沿不同方位采样周边山脊，计算最大仰角形成地平线曲线；将太阳方向对应的地平线高度与太阳高度比较，求预计进入/离开山影的时间。DSH 确定适合实际场景的搜索半径、角度/距离采样与缓存，保留计算范围、数据分辨率和版本，考虑远距离曲率；不把有限范围结果说成绝对无遮挡。

GLO-30 是约 30 米地表模型，不是精确裸地，也不能可靠分离建筑和树木。第一版只交付山体尺度估算，用在时间线、机位光线与地图说明；无数据或覆盖不足显示未知，不默认为无遮挡。地形晴空直射可能性与云层影响分别表达。

### 5.2 预报与主动检查

Open-Meteo 提供全球预报，默认 7 天、最多请求 16 天；具体字段可用时距以返回值为准。中国有全球模式覆盖，不据此承诺每个机位局地准确或国内网络直连稳定。读取逐时云量、降水概率/量、风与阵风、温度等，保存获取时间、预报有效时间、数据源和已知模型信息。

行程显示拍摄地点当地时间。**待执行计划按账户 IANA 时区每天 08:00、16:00、23:00 检查**，与行程时区分开；账户时区尚未设置时应由用户设置，不能取服务器时区猜测。

控制面负责调度、取数、保存快照及触发 DSH；DSH 读取新旧预报、已确认停留点及其光线需求、最近已接受的安排和既有提醒，自主判断是否显著影响机位。阈值仅作为参考信息，不是调用模型的硬门槛：降水概率跨过 60% 且降水量达 0.5 mm/h；依赖直射光时云量增至少 30 个百分点且达 70%；阵风跨过 10 m/s。模型可按实际拍摄需求判断其他明显影响，不把云量等同于“太阳必然被遮”。

每次取得适用的新预报后交模型判断，产生的 token 归该计划；相同未更新数据无需重复模型判断。不受影响就安静保存检查结果；有影响则生成具体停留点的前后对照进现有收件箱。未应用不修改计划，同一变化不在下一次检查重复通知。可用最近检查追踪新变化，同时保留用户接受预报的基线，避免忽略逐步累积的变化。

目标日期尚不在可预报范围时保存等待状态；进入范围后检查，不将气候均值当当天预报。未取得天气时记录失败而非“无变化”。本机服务运行时关闭网页不影响；服务关闭则暂停，重启后对仍待执行且错过检查的计划补查一次，不补跑所有历史时点。

最后一个停留点结束、取消计划、归档或删除档案后停止监测。后台建议绑定生成时计划修订；应用时确认仍适用于当前计划，不覆盖用户后续修改。调度只实现此业务，不建设通用自动化平台。

## 6. 搜索、参考图和 DeepSeek 视觉

### 6.1 全网搜索，来源偏好不构成白名单

沿用 DeepSeek Search/Fetch。工具支持普通查询、按域名表达偏好、读取网页与保存来源；模型自主决定检索词、站点和顺序。不规定逐站检索、次数、失败后的操作剧本。

| 需求 | 优先考虑的来源 |
|---|---|
| 国内机位、近期实拍 | 小红书、B站、当地摄影师文章和游记 |
| 海外机位、作品 | Instagram、Flickr、500px、摄影师个人站、当地摄影社区 |
| 穿搭、姿势、色调 | 小红书、Instagram、Pinterest |
| 路线、现场环境 | B站、YouTube、当地旅行/徒步资料 |
| 开放时间、拍摄规定 | 场馆、公园、景点管理方官方页面 |

以上是来源偏好，不排斥其他网站。搜索索引不保证能读取小红书/Instagram 的完整图文；登录或访问受限时返回真实可用的摘要/原链接，不能声称读过全文或看过图片。不为本轮建设专用爬虫、共享登录 cookie 或绕过访问限制的系统。

真实参考图保存原网页 URL、可展示的图片引用、作者/平台（已知时）、来源时间及关联地点。区分“该机位实拍”和“风格参考”，不能仅凭相似照片断言准确机位。保留署名，不生成模拟样片或服饰图；无可用图片时显示来源卡，不拿无关图片顶替。计划书使用可保存/展示的参考图，保留来源；拿不到图片就如实给链接。

### 6.2 图像理解与配置

继续使用 DeepSeek，不接第二家视觉模型。用户上传图片成为当前档案资产，经既有 Provider 代理进入支持视觉的模型；工具也可将已取得且有权读取的参考图交模型分析。返回光线、色调、构图、姿势等观察以及不确定的时段/焦段推测，形成钉在计划上的“想要的感觉”。无 EXIF/其他证据时不得把焦段和拍摄时间当已知事实。

官方视觉文档当前明确列出 `deepseek-flash` 及 Anthropic 兼容图像输入。用户希望使用 DeepSeek 4.1 系列；**实际 model ID 和视觉能力以实施时当前配置及官方接口为准，不凭产品称呼虚构 ID**。沿用现有模型配置入口表达视觉能力；所选主模型可看图时直接输入，只有配置为另一个 DeepSeek 视觉型号时才通过同 Provider 的读图调用接入。缺能力明确提示配置缺失，不静默换其他服务商，也不假称看懂。

## 7. Agent 工具与写权限

以下为能力语义，不是最终 API 名称。账户/档案身份从可信会话取得，模型不自行指定他人账户。

| 能力组 | 足够使用的工具 |
|---|---|
| 地理 | 查地点/消歧、查询范围内地图要素、步行路线、坐标转换适配 |
| 光线与天气 | 太阳时段/方向、山体地平线/见光估算、逐时天气与获取时间 |
| 搜索与图像 | 全网搜索、网页读取、参考图读取/关联、图像理解 |
| 画布 | 读取画布、视野控制、点线面/箭头/笔记增删改、关联地点/图像、撤回画布改动 |
| 计划 | 读计划、增删改候选、提出修改、逐点/批量确认、应用已批准修改、完成/取消计划 |
| 账户资料 | 按需查/读模特与器材、提出或执行明确授权的增删改、将选定资料快照加入计划 |
| 成果 | 预览精简/详细计划书、生成 PDF 并关联档案、读取计划用量 |

权限原则：

- 查资料、读图、查看地图、调整视野、草图与候选编辑，在本次已授权规划范围内自主进行。
- 候选变已确认、助手主动更改已确认地点/日期/时段/路线或删除已确认停留点，须用户接受具体内容；支持整份批准。
- 用户明确要求的修改与删除直接执行，不重复问。页面点击即为相应动作的授权；不能一项动作出现两次审批。
- 已批准设计范围内补充构图、引导词和参考资料无需逐条审批，但不借此改变已确认行程。
- 天气调整以“应用”生效；改写账户资料只保存用户填写或明确确认过的内容。
- 明确要求生成计划书即可生成并自动入档，不再问是否挂载。未确认计划的预览/导出明确标草稿，不能冒充最终成果。

不通过长篇提示词教模型做事。程序维护对象、来源、授权、版本与操作结果；工具说明交代用途、必要参数和底线即可。

## 8. 账户级资料与后续共享记忆

模特、器材进入控制面管理的账户资料库，独立于探索档案。每项有稳定 ID、类型、内容、修订及确认来源；同账户各台助手通过工具按需读取，不向每轮上下文倾倒全部资料，其他账户不可读。

- 模特：称呼、身高、风格、经验、衣橱要点、确认过的合作经验；不能从照片擅自写入推断的人物资料。
- 器材：机身、镜头、焦段和用户确认的相关属性，支持修改/删除。
- 页面和助手都支持增删改查；“记住我有这支镜头”已是确认。助手新推测或新总结必须先经用户确认。
- 计划选择资料时保存来源 ID、修订及当时快照。资料更新不偷偷改旧计划，再次编辑可显式采用最新资料。
- 删除资料后后续工具不可继续读该记录正文，也不自动重建；旧计划快照和已导出计划书仍保留，用户已确认该范围。
- 相关变化进入既有业务事件与下一次相关模型上下文，不向无关档案广播全部资料。

这是共享资料的第一步，不实现自动记忆提取、向量检索或通用记忆框架。未来共享记忆引用这些稳定实体及确认来源，不能绕过它们的修改/删除语义。

## 9. 计划书与产物

两版共用同一计划修订：精简版为 A4 一页，含路线小图、时间表、每点一行要点；详细版为一页总览及每个停留点一页，按需呈现构图、器材、光线、模特引导、服饰、真实参考图、规定和雨天备选。

网页按手机宽度自适应单栏，纸张按 A4 排版；手机适配指网页，不宣称固定版式 PDF 会自动重排。若停留点数量使一页纸无法清晰容纳，预览说明需精简内容，不能静默裁切。未知规定/备用点不编造。

Claude 写网页及打印模板；DSH 使用 Playwright 加载该版本的打印页面，待字体、图片与地图静态图准备后生成 PDF。默认静态路线图采用矢量底图及必要来源署名；不打印仍在加载的交互画布。简版、详版分别保存文件，记录计划修订、版本、生成时间、类型与打开入口，成功后复用档案成果关联。网页当前计划可继续编辑，已生成 PDF 不自动覆盖。

沿用当前文件/资产存储，不新建产物平台。打开档案成果能看到真实可下载文件；历史成果缺文件时如实显示不可用。

## 10. 模型用量

本轮不设置新的每计划预算金额或预算设置界面，也不启动真实调用。原有全局凭据与真实执行底线保持；实施阶段的付费运行按当时授权，不把本文视为无限付费授权。

每次模型请求记录实际 Provider/model ID、输入/输出 token、可得的缓存/推理用量、账户、档案、计划、运行与用途。用途至少区分计划编排、图像理解、天气判断、天气调整；一次调用兼做判断与建议时记为同一次请求及相应用途，不拆成两笔。视觉 token 以供应商返回为准，不用图片数猜测。

复用现有唯一 usage 写入入口，汇总每计划总量与按模型/用途分项；后台调用同样归属计划。缺失用量标未知，已知部分可以展示但不能假称完整总量。Search/Fetch 等按次调用另列次数/费用（有真实值时），不混成模型名称和生成 token。价格不可得则未知；已有费用估算统一按峰值费率，不建设峰谷精细计价。

## 11. Claude 真实页面验收

先由 Claude 定前端契约；DSH 完成相关开发测试并交付后，Claude 像真人一样在实际页面使用、回答助手问题、判断功能是否达成。不开固定模型验收脚本，不按措辞或调用顺序判对错。

| 编号 | 做什么 | 应该看到什么 |
|---|---|---|
| E1 | 用真实国内地点和海外地点查看地图，切换矢量/卫星，查询地点并生成一段步行路线 | 图层真实、来源可见、国内点线无明显坐标错位，步行距离/时间来自服务；切换保留内容 |
| E2 | 从旅拍意图和用户参考图开始，让助手自主搜索和编排 | 真实读图形成感觉卡，搜索结果有可打开出处；不伪造图片、地点或规定 |
| E3 | 观察助手移动视野、圈街区、画箭头、贴笔记、创建候选；手动拖图并恢复跟随 | 中间逐步呈现，右侧对应实际操作记录；草图/正式路线可区分，助手不抢用户视野；刷新恢复画布 |
| E4 | 用固定机位、街区、顺路点排计划；分别逐点留下、批量批准、直接要求修改 | 三种类型工作，地图/聊天/时间线同源同步；明确要求不重复审批，未批准建议不改正式安排 |
| E5 | 在真实山体附近点位查看日出、预计见光、山影与逐时天气，再查看海外时间线 | 日出与山后见光有区别，地形估算/未知明确；地点时区正确，不展示固定京都示例 |
| E6 | 页面及助手保存、修改模特/器材，另开档案或其他台读取；删除资料后查看旧计划 | 同账户按需共享，只存已确认内容，推荐使用已有器材；新查询不可读已删除资料，旧计划快照保留 |
| E7 | 确认整份计划待执行，检查三次时点与账户时区；关闭页面并查看一次后台检查结果 | 控制面按账户 08/16/23 调度，页面关闭不影响；无明显变化保持安静，token/模型计入计划 |
| E8 | 用真实前后预报完成天气影响判断；出现调整建议时先不应用，再应用 | 有影响才进收件箱，显示具体机位前后对照；应用前不改计划，应用后同步；同一变化不重复提醒 |
| E9 | 生成两版计划书，在手机宽度查看网页、打印预览，并从档案打开 PDF；再修改计划 | 简版一页、详版总览加停留点页，来源与地图正常；旧 PDF 保留当时版本，新计划不覆盖 |
| E10 | 查看完成编排、读图及后台检查后的计划用量；重新打开档案 | 模型和输入/输出 token 可按计划及用途查看，未知不记 0；计划、画布、成果和状态持久存在 |

E7 的时点计算和补查由相关确定性开发测试覆盖，不要求 Claude 守到三个时点；可调用同一检查入口立即跑真实预报，不能声称这等于已自然触发所有时点。E8 如当日无真实显著变化，不伪造天气或强迫模型报变化：如实记待验，可使用已保存的真实前后预报通过同一判断入口验证。模型意见以功能含义验收，不能机械断言某个固定阈值一定触发。

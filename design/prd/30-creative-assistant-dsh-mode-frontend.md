## 一、页面要改的地方（就三处）

1. **助手改成「续一句」**：建会话仍用 `POST /v1/kernel/runs { dossierId, query, mode, workId?, sceneId? }`；
   之后每发一句改调 **`POST /v1/kernel/runs/:id/messages { query }` → 202 `{id, state:'running'}`**，
   回复还是写在同一条事件流里（`user/message`、`assistant/message`），按 `runId` 订阅不变。
   一轮结束后 run 仍是 `completed`，可以继续续；想新开就再建一个 run。没有自动过期。
   回复是模型写的 Markdown（列表/表格/加粗都可用），页面现有排版够用。
2. **新增「让模型判规则」**：`POST /v1/creative/worlds/:id/rules/judge`（无 body 也行）→
   `{ judged, skipped, cost, check }`。结果并进 `check.conflicts`，`kind: 'rule_model'`、`severity: 'suspect'`
   （黄色、附原句和理由），自动显示在检查面板。我已在 `Panels.tsx` 的 `KIND_ZH` 加了一行
   `rule_model: '规则（模型判的疑似）'`（类型兼容，不动样式）。建议放在检查区旁边，标上花费。
   规则和事件没变时再点不花钱（返回 `judged: 0`）。
3. **1C 那几条不用改页面**：影响面板、按作品看、sync 标注都只是后端修好了，接口形状没变。

## 六、复验后的修正（2026-11-09 晚，提交见 git log）

**C2 场景级引用也能接受了。** 「跟着改」之后「让助手改」分两种引用走：

| 引用方式 | sync 记什么 | 改稿提议 | 接受时 |
|---|---|---|---|
| 正文标注（正文里写了地名/人名） | `{itemId, sceneId, para}` | `range {para,from,to}`，`before` = 那一段原话 | 替换那一段 |
| 场景 `eventIds` 引用（正文没写） | `{itemId, sceneId}`（没有段号） | `range: null`，`before` = **整场原文** | 整场替换 |

- 两种情况都不会再把改稿接到末尾；找不到原话回 409 `TEXT_STALE`（这次的意思才是对的：正文确实在出提议之后变过）。
- `marks` 里的 `sync` 仍带段号（没有段号时是 0），页面按它画橙线即可。
- 现场那条旧提议 `4c4007f4` 已经按「整场」补齐 `before`（= 当前整场原文 38 字），可以直接接受，接受后待同步减 1。

**助手花费挂到会话上了**：`usage_record.run_id` 现在写的是对话的 run id，可以按会话算总花费。
**判过的规则不再进「未覆盖」**：`check.uncovered` 只留模型也判不了的规则。
**第 4 问（影响清单列全部作品）**：契约 §6.2 的本意是「每部作品现在用这条的哪个版本」——凡是基于旧版的作品都列，
包括正文和事件都没引用的（它们「采用后」的检查结果通常等于现状）。要不要在面板上只显示「真正受影响」的，
属于展示选择；需要的话我加一个 `affected` 标记字段（要动契约，先回来说）。

## 五件事（按顺序）

### 1. 代码合到一处（先做，也是这次合并的方式）

- **现状**：前端源头在主仓库 `slim/frontend`；后端在 `~/.codex/worktrees/research-foundation/ReinLab` 的 `slim/backend`。两边靠同步清单手工复制，`main.tsx`、`read-live.ts`、`ReadMode.tsx` 这类文件反复出现两边不一致。
- **要定**：
  - 合成一个仓库、一条主线，目录怎么分（前端 / 后端 / 数据适配层）；
  - 两个分支怎么合进来、主线叫什么；
  - Claude 和 DSH 各自负责哪些目录，以后不再「同步」。
- **验收**：一个仓库里一条命令起整个栈；在主线上，精读还能照 run16 的样子走完。

### 2. 运行生命周期（七台共用）

- **现状**：出过好几次「挂住、不收尾」；等人回答时占着会话（`SESSION_BUSY`）；跑之前常要手工跑 SQL 清理残留的 run 和待批卡。DSH 刚做了「等人审批时释放租约、10 分钟过期」，但只覆盖了审批。
- **要定**：一个 run 从开始到结束的状态；等人（审批、提问）时怎么处理；任何失败都在有限时间内进入终态；残留怎样自动清掉（不再需要手工 SQL）。
- **验收**：中途关掉页面、断网、不回答提问、重启栈之后，都不会留下挂住的 run，下一次直接能用。

### 3. 工具与插件规范（每个台一个 DSH 插件）

- **现状**：只有精读插件。工具出错的格式是这一轮才补上的（`{code, message}`）。
- **要定**：
  - 一个台的插件怎么写：能用哪些工具、哪些动作要批准一次、出错时返回什么；
  - 共用工具（检索、网页、文件、卡片）放在哪里；
  - 提示词只留底线。
- **验收**：照着规范给另一个台（建议课程台）搭出一个最小插件，能跑起来。

### 4. 档案模型（七台通用）

- **现状**：只有精读有真实档案；七个台的 Files 都是写死的 4 份；刷新以后档案列表也接不上。
- **要定**：
  - 档案是什么：类型、标题、状态、属于哪个台、和 run 与产物的关系；
  - 档案库怎么列、怎么新建、怎么「续上次」；
  - 前端拿数据的接口（Claude 会按你的语义定前端契约）。
- **验收**：在任意一个台新建档案，关掉再打开，内容和进度都还在；选台页的 Files 显示真实档案。

### 5. 登录会话

- **现状**：登录只存在页面内存里，一刷新就要重新登录。
- **要定**：会话存在哪里才安全、多久过期、怎么续期、怎么退出。
- **验收**：刷新、关掉标签再打开都不掉线；点「锁定」能退出。

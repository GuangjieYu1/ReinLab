# 16 · 创作台 · 用户体验结论（用户与 Claude，2026-11-05）

为什么现在做：群研做完了，学习台暂停（已定的答案记在 Claude 的记忆里，回头直接用），用户定下一阶段先做创作台。

现状：`src/components/workbenches/creative/` 全是前端示例，示例作品是《魔戒》同人《红皮书的最后一页》。页面分三个面：
- 世界观：关系图、年表、地图，加上设定卡和检查矛盾；
- 小说：章节和正文，有补全、续写本场、改写语气、转为分镜；
- 视频：一句话搭白模，再摆机位、分三轨时间轴，最后出成片（目前是占位）。

设计见 [WORKBENCH_SPEC.md](../WORKBENCH_SPEC.md) 第二章。旧架构写的是「出图和视频第一阶段暂缓」（[ARCHITECTURE_BENCHES.md](../ARCHITECTURE_BENCHES.md)），本轮改掉这一条。

## 1. 已定

| 项 | 结论 |
|---|---|
| 范围 | 三个面全做，包括真实出图和成片 |
| 分批 | 文字 → 出图 → 视频，每批在真实页面上验收，和群研一样。MVP-1 做世界观和小说的双向打通，加上矛盾检查；MVP-2 做立绘和三视图；MVP-3 做分镜、白模和成片 |
| 两个方向都要 | ① **先建世界观再写小说**：用户说一个想法，设定顾问边问边建人物、地点、关系、年表，用户确认后入库，再写小说；② **导入小说提取世界观**：用户贴入或上传小说，AI 抽出实体、关系、年表，用户确认后入库。两条路最后都落到同一份世界观，小说和镜头都引用它 |
| 小说谁来写 | 两个方向都支持，不定死「AI 写」还是「人写」。正文里人和 AI 都能动，现有的补全、续写本场、改写语气照用 |
| 首例 | 两个：一个从世界观生成小说（新起一个原创短篇）；另一个从小说提取世界观，用公版中文经典（比如鲁迅《故事新编》或《聊斋》里几篇） |
| 出图 / 成片模型 | 当前用火山方舟：Seedream 出立绘和三视图，Seedance 出视频，它支持白模加机位生成成片，和视频面参照的做法一致。**要做成多平台可配**，换平台不改前端。key 由用户自己加进 `local.env`，只在进程内存里读 |
| 花钱 | **先记钱，不设硬上限**（用户 2026-11-05 定，只适用于创作台）。照样按峰值费率估算，用量未知就标未知。Claude 验收前照旧先报预算 |

## 2. 留给 Codex 和用户去拷问的

- 世界观存在哪里，怎么做检查：旧架构写的是 L4 事实加 pgvector，是不是沿用。
- 矛盾检查查到什么粒度，人物、世界、情节、时间线四类够不够。查出问题以后，是改正文、改设定，还是标成伏笔。
- 小说能写多长；按章还是按场景生成；大纲要不要先过一张确认卡。
- 导入时文本多长，切分怎么做；抽出来的实体怎么让用户逐条确认或改。
- 立绘和三视图怎么保持人物一致，比如设定卡带参考图、同一人物的多张图互相参照。
- 成片怎么从白模和机位走到 Seedance，单镜多长，每镜出几个候选。
- 角色：设定顾问、写作助手、分镜导演，各用哪些工具，彼此怎么隔离。
- 生成的图和视频放在哪里（账户卷还是 Storage），档案库里怎么列。

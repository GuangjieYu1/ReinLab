为什么现在做：群研做完了，学习台暂停（已定的答案记在 Claude 的记忆里，回头直接用），用户定下一阶段先做创作台。

现状：`src/components/workbenches/creative/` 全是前端示例，示例作品是《魔戒》同人《红皮书的最后一页》。页面分三个面：

- 小说：章节和正文，有补全、续写本场、改写语气、转为分镜；
- 视频：一句话搭白模，再摆机位、分三轨时间轴，最后出成片（目前是占位）。

旧设计见 [WORKBENCH_SPEC.md](../WORKBENCH_SPEC.md) 第二章，本文件改掉其中两处：
- 一个项目原本只对应一部作品，现在改成**一个世界观挂多部作品**；
- 世界观原本是三个并列的视图，现在改成**以地图为主**。

旧架构里「出图和视频第一阶段暂缓」（[ARCHITECTURE_BENCHES.md](../ARCHITECTURE_BENCHES.md)）这一条也作废。

调研依据：三份同题调研，分别来自群研、ChatGPT 深度研究、DSH 单人，对比见 [BENCHMARKS.md](../BENCHMARKS.md) 2026-11-05。三份都认为：整条链没有人做通；人物轨迹、硬性的时空检查、跨作品的设定版本，这三样要自己做。

## 1. 核心模型

```
项目 = 一个世界观（canon）
  ├ 地图     分层：世界 → 城市 → 建筑 → 房间（房间这层就是场景白模）
  │           底图 + 改造层（历史 / 未来 / 架空），改造层可以随时间生效
  ├ 实体     人物、地点、物件、组织、关系
  ├ 事件账本 谁 · 在哪 · 何时（起止）· 做什么 · 出处 · 状态
  │           状态：原文明写 / 推断 / 作者确认 / 未知；只有「明写」和「作者确认」算设定
  ├ 规则     交通方式和速度、历法、世界自己的规则（如传送）
  └ 作品 ×N  小说 / 电影 / 漫剧（以后加游戏）：引用事件 + 自己的取舍和视角 + 局部改写
              每部作品记着自己基于哪一版设定
```

- **人物轨迹由事件算出来**：两个事件之间，人物沿路网按交通方式插值移动。拖动时间轴，就能看到每个人此刻在哪、在做什么，像战略游戏一样。
- **矛盾检查交给程序判**，不靠 AI 猜：
  - 同一时间出现在两个地方；
  - 路上时间不够；
  - 人物死后又出场；
  - 不在场却参与了互动；
  - 地点层级对不上，比如进了房间却没进那栋楼。

  界面照抄 Aeon Timeline：违规标红，可以选「移动这一条 / 移动对方 / 删掉约束」，也能一次全部处理。AI 只负责从文字里抽事件、解释矛盾、给出修改建议。
- **改了设定**，系统列出受影响的作品、章节和镜头，由作者逐一决定：跟着改、保留旧版，还是改设定本身。不偷偷改已经写好的作品。参照 articy:draft「原文改了，译文标为过期」的做法。
- **AI 只提议**：抽取、续写、补全、模拟出来的东西一律先进「待确认」，作者点头才进入设定。原文没写的标「未知」，不编。

## 2. 已定

| 项 | 结论 |
|---|---|
| 范围 | 三个面全做，包括真实出图和成片 |
| 分批 | 文字 → 出图 → 视频 → 模拟，每批在真实页面上验收：<br>**MVP-1 文字全链**（用户选的，不缩成垂直切片）：分层地图、事件账本、时间轴加轨迹插值、硬矛盾检查、作品引用事件和设定版本；小说两个方向都走通，从世界观写出小说、从小说抽回世界观。<br>**MVP-2** 立绘和三视图，人物有稳定的资产 ID。<br>**MVP-3** 房间层的场景白模、人物白模（按身高体型摆的人偶）、机位、Seedance 成片。<br>**MVP-4** 让人物自己活一段（AI Town 式模拟），产出只当素材，进「待确认」 |
| 地图 | 真实地图**复用探索台的底图**（MapLibre + OpenFreeMap 的 OSM 矢量数据，莱茵配色），但只把它当底图。在底图上叠**改造层**，按故事需要隐藏、新增、改名、改样式：<br>• 历史：去掉现代道路和建筑，加上城墙、古道、旧地名；<br>• 未来：加上新的建筑和交通；<br>• 架空：用生成的地图当底图，比如 Azgaar（MIT，可商用）。<br>改造层可以设生效时间段，地图随时间变化，参照 World Anvil 的 evolving maps。高德只用于探索台，不进创作台的底图，因为它禁止缓存，底图也不能拿去出图出片 |
| 轨迹 | 按路线插值。交通方式和速度按世界观设定，真实地理的路程用路网算 |
| 两个方向都要 | ① 先建世界观再写作品：用户说一个想法，设定顾问边问边建，用户确认后入库；② 导入小说抽世界观：AI 抽出人物、地点、事件和时间，每条带出处（章、句）和状态，用户逐条确认 |
| 小说谁来写 | 不定死。正文里人和 AI 都能动，补全、续写本场、改写语气照用 |
| 首例 | 两个：一个原创短篇（从世界观写出小说）；一部公版中文经典，比如鲁迅《故事新编》或《聊斋》几篇（从小说抽世界观，走「真实底图 + 历史改造层」） |
| 出图 / 成片模型 | 当前用火山方舟：Seedream 出图，Seedance 出视频；**要能换平台**，换平台不改前端。key 由用户加进 `local.env`，只在进程内存里读。模型和平台以后在设置页里配 |
| 花钱 | **先记钱，不设硬上限**（只适用于创作台）。按峰值费率估算，用量未知就标未知。验收前按 [COST_LEDGER.md](../COST_LEDGER.md) 报预算 |

## 3. 可以照搬的（来自调研）

- **LegendKeeper**：地图一层套一层往下钻，地图上的点就是一篇设定。
- **World Anvil Chronicles**：事件 ↔ 地图上的点 ↔ 时间线三向跳转；时间线分泳道，可以多条并行。
- **Campfire**：每个人物占一行的时间线。
- **Aeon Timeline**：约束类型、违规标红、逐条或批量处理、自动重排。
- **Kanka 的历法模型**：年月、星期、季节、月相、闰月。只参考数据模型，代码许可禁止商用。
- **OnlyWorlds**（MIT）：把「事件」和「叙述」分开，`Map.parent_map` 表示地图层级。底层数据可以直接参照它。
- **articy:draft**：设定是唯一的事实来源，下游标「已过期」。
- **Seedance 2.5** 白模控制：白模里的人物只留躯干，不然四肢会僵。**Intangible** 把参考图绑在 3D 物体上，靠这个保持跨镜头一致。
- **可灵 Element**：一个人物用 2–4 张参考图，还能绑定声音。人物资产 ID 按这个方向设计。

## 4. 留给 Codex 和用户去拷问的

- 事件账本和规则引擎怎么存、怎么查。时间段关系用 Allen 区间代数，再加上路网算的路程时间。要不要上求解器（OR-Tools / Z3）？
- 改造层的数据格式：怎么对 OSM 的元素做隐藏、新增、改名；怎么和生效时间段绑定。
- 地图层级之间的坐标怎么换算；房间层用什么格式，好直接变成白模（glTF）。
- 中文小说抽取怎么做：人物别名合并、共指、相对时间（「三天后」）、古地名对到底图上。抽出来的待确认清单长什么样。
- 设定版本：作品锁定在哪一版，影响分析怎么算，界面怎么让作者逐条决定。
- 小说能写多长；按章还是按场景生成；大纲要不要先过一张确认卡。
- 角色：设定顾问、写作助手、分镜导演，各自用哪些工具，彼此怎么隔离。
- 生成的图和视频放在哪里，档案库里怎么列。

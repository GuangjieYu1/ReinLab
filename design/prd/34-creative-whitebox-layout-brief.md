# 34 · 白模改成「房间壳 + 关系布局 + 求解器」· 给 DSH 的开场

日期：2026-11-10。分支 `codex/creative-3`（接着 3A）。

输入：[20-creative-contract.md](20-creative-contract.md) **§13.8**（刚补）；对比结论见 [BENCHMARKS.md](../BENCHMARKS.md) 2026-11-10。

## 为什么改

3A 两轮验收，白模一直出界、超高、悬空。根子不是提示词写得不够，是做法：让语言模型心算每个部件的三维坐标，连墙和顶棚也让它算。用户判断：「根据场景生成建模应该有专门的开源工具」。开源里最对口的是 AllenAI 的 Holodeck：**模型只说物件之间的关系，坐标交给约束求解器**，硬约束保证不出房间、不相撞。

另外查到一个直接的 bug：`world.ts` 的 `insideOutline` 用射线法，压在轮廓线上的点右、后两边算外面——所以东墙（x=5）、南墙（z=4）必被判出界，西墙、北墙能过。

## 要交的

1. **房间壳**：按 `place.room` 生成墙（每条边一段，厚 0.2 米朝屋里）、地面、顶棚（在层高以下）、门窗洞（`openings`）。
2. **求解器**：按 §13.8 的硬约束、软约束摆 `LayoutItem`，结果写成普通的 `whitebox.prim.add`（带 `from`、`key`），预览、接受、版本、glTF 都不用改。没满足的软约束写进 `unmet`。
   - 可以移植 Holodeck 的 DFS 求解器；**接入代码前先核实它的 LICENSE**（我记得是 Apache-2.0，没核实到），交付单写清楚用的是移植还是自写。
3. **工具**：`propose_whitebox` 改成交 `openings` + `items`（不写坐标）；没有房间几何时可以一并带 `room`。「改一下」按 `key` 合并，没提到的件不动；作者拖过的件当固定障碍。
4. **顺带修**（§13.8 末尾那五条）：边界判断对称；交提议、预览（带不带 `workId`）、接受用同一套校验；run 的 `placeId` 要用上；白模和镜头一轮交完；正文是占位字也走兜底。
5. 提示词底线：不写坐标，只写尺寸和关系；白模和镜头一轮交完。其余不教。

## 不做

- 真模型资产（八仙桌、柜台的 3D 模型）：白模阶段仍是方块；
- 前端：拖家具、`unmet` 显示我来做（§13.8「页面」）；
- 3B 出片：等这个通过以后再开工，开工前我报预算。

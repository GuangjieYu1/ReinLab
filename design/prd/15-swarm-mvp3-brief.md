# 15 · 群研 MVP-3 · 给 DSH 的开场

日期：2026-11-03。分支：`codex/swarm-3`（从 main `4842fba` 拉出）。输入：[12-swarm.md](12-swarm.md)（已批准，PRD §3–§10）、[13-swarm-contract.md](13-swarm-contract.md)（前端契约，§2 标「3」的接口、§3 事件、§5 收件箱新卡、§6 委托）。前两阶段的验收记录：[swarm-1](../walkthroughs/swarm-1/RESULTS.md)、[swarm-2](../walkthroughs/swarm-2/RESULTS.md)。

MVP-3 做完才算群研能交付（PRD §9）。内容多，**分三批做，每批一个提交，做完一批就通知 Claude 验那一批**，不要三批一起交。

## 第一批：审查与门禁、多轮推进

用户能看到的：候选结论被独立反驳、独立核实，状态从「候选」一路走到「已核实 / 有争议 / 已证伪 / 证据不足」；负责人按缺口推进到第 2、3、4 轮，前两轮各路线互不相看，第 3 轮起交叉借鉴；最后出正式报告，正文只放已核实的结论。

- `research_review_claim`（PRD §5）：反驳和核实分成两个任务、两个人做。核实的人不能核自己交的结论，要回到原始出处去核（文献回原文；计算回实际运行；证明看命题和假设），不能只复述反驳意见。每条结论最多反驳两轮，结论改版不重新计数；两轮后还有争议就标「有争议」。主张或证据一改，旧的核实作废，要重核当前版本。审查结果落成 `Review`，同时推 `review` 和 `claim` 事件。
- **多轮推进**（PRD §3）：一轮 = 负责人派出一批任务 → 收齐产出或确认失败、阻塞 → 综合、质疑、调方向。轮次和阶段（独立 / 交叉）由服务端推进，`run.round` / `run.phase` 跟着变；第 3 轮起按 PRD §4 用精简的 Context Packet 开放已核实或标明的成果，只转授权产物，不转整段会话和别人的目录。
- **额度和收尾**（PRD §3）：快到额度时进 `near_limit`，在 `report.nextSuggestion` 里写新发现、剩余缺口、建议追加多少，等用户批准才继续（收件箱卡 `swarm_extend` 放第二批，这批先把状态和建议做出来）。到限就停止新增任务、保存阶段结果，不偷偷延长模型调用。
- **报告门禁**（PRD §5 末）：正式报告的正文只放绑定了当前版本独立核实的结论，其余进局限、争议、未核实、待确认这几区。报告前还有分歧时进 `awaiting_review`（收件箱卡 `swarm_divergence` 放第二批）。`report.state` 从 `stage` 变成 `final` / `partial` / `unresolved`；`answer` 写最强的已核实结论，没有就是 null。
- 前端这边由 Claude 接：结论状态徽标、详情里的审查记录、汇总的正式报告分区。

## 第二批：用户干预与收件箱新卡

用户能看到的：契约 §4.4 和 §5 那些操作都能用，每一步都有真实回执。

- 干预（PRD §6，契约 §2 `interventions` 标「3」的那几种）：`mention`（@某队员，定向投递，显示已接收 / 已投递 / 已回复）、`redirect`（改方向：受影响的任务停下、旧证据保留、负责人出新版本计划并自动继续；扩大原问题范围要走 `swarm_scope` 卡）、`add_member`（走 `swarm_add_member` 卡，批准后由负责人创建，不能绕过 16 人的累计名额）、`extend`（走 `swarm_extend` 卡）。
- 收件箱新卡（契约 §5）：`swarm_add_member`、`swarm_extend`、`swarm_scope`、`swarm_divergence`，字段照契约放在 `effects[0]`；研究中必须由人回答的问题沿用 `question` 卡。页面和收件箱是同一张卡，重复提交返回同一回执。
- 前端由 Claude 接：解开「加人 / 改方向」两个按钮，收件箱四种新卡的卡面，计划差异卡。

## 第三批：精读关联、跨台委托、首例全流程

- **精读关联**（PRD §8，契约 §2）：`POST /runs/:id/claims/:claimId/read { evidenceId }` 用同一材料版本和定位建精读或接着精读，返回 `readDossierId` 和 `href`。研究员仍然不带下载 / 登记论文的工具（用户 2026-11-03 定）；要细读，走这条关联。精读结果回到对应的任务和结论；如果原运行已经结束，就记成后续版本，不能悄悄改已发布的报告。
- **跨台委托**（PRD §8，契约 §6）：发起、确认、查看、决定四个接口，以及 `DelegationResult` 结果卡。按 `delegation_id` 幂等：重复回调更新同一张卡、版本号递增。先接**一个**源台，选最容易接的那个，在交付单里写明选了哪个。采用只是在源档案里记一笔、挂上引用，不覆盖源内容。
- **首例全流程**（PRD §10）：在真实研究台跑一遍「多 Agent 数量增加是否一定提高研究质量？」，要能看到：
  - 不同路线；
  - 真实的反驳和核实；
  - 中途改方向「只看相同总 token 预算下的比较」；
  - 刷新或重起后不丢、不重复；
  - 到限时给出追加建议；
  - 正式报告；
  - 从源台发来同一个问题，并收到结果卡。

  这一项由 Claude 在页面上验；你只要保证链路通，交付单里给出能直接打开的那条运行。

## 不做

- 语义检索增强、复杂的动态扩编、精细的历史回放、其余源台的接入（PRD §9）。
- 不做跨进程的大群、任务租约、成员回收。

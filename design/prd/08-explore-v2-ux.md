# 探索台第二版 · 用户体验结论（用户与 Claude 头脑风暴，2026-11-01）

第一版（计划 + 计划书）已合入 main，体验依据见 [05-explore-ux.md](05-explore-ux.md)，PRD 见 [06-explore.md](06-explore.md)。本文件只补第二版的体验决定；技术方案由用户和 Codex grill 后写 PRD。现有前端里现场（FIELD）、回顾（REVIEW）、机位（SPOT）三个面的演示版视觉和交互是起点。

## 1. 现场

- **设备**：iPad 横屏和手机都要精心做，各一套布局（不是简单缩放）。手机信息少而大，单手可用。
- **离线可用**：出发前把这份计划、沿线地图、光线（太阳、山影 / 楼影）、最近一次天气缓存到设备上。没信号时能看计划、看此刻的光、看引导词、点"拍到了"、记一句话；记录先存在设备上，有网后自动同步。助手重排、取新天气需要联网，离线时照实说"现在没网"。
- **实时定位**：地图上显示我在哪；走到停留点附近自动切到这个点；"该走了"——按真实步行时间和下一个点的拍摄窗口提醒（比如"再拍 8 分钟就得出发，否则赶不上白鹭坡的日落"）。定位只在现场模式里用、只用于这份计划，不在后台持续记录轨迹以外的东西（"实际轨道"见回顾）。
- **一眼要看到**（第一版已定）：现在 / 下一个机位 + 倒计时、此刻的光、引导词（大字可直接念给模特）、"拍到了" + 一句话记录。
- **情况变了**：几个常见情况做成大按钮（下雨了、晚到了、人太多、光不对），也能打字或语音补一句。助手给出前后对照，点"应用"才改计划（沿用第一版的审批 / 应用语义）。

## 2. 回顾

- **导入**：全部原图上传（相机卡导出的 JPG，可能几百张）。要能批量拖入、显示进度、断了能续传。
- **自动对时**：用现场"拍到了"的打卡时间和照片拍摄时间，自动算出相机时钟偏差；算不准（没打卡、偏差不一致）再问我。手机拍的照片自带位置就直接用。
- **落位**：照片按（校正后的）拍摄时间落到对应停留点和地图位置；时间线上叠"实际"轨道，和计划对照。
- **助手做四件事**：
  1. **挑片**：看照片评对焦、闭眼、构图，每个机位推荐几张，我来定。
  2. **计划 vs 实际对照**：哪些点拍了、晚了多久、哪个没拍、光是不是和预想一样。
  3. **写游记**：用现场的碎片记录和照片写一篇。
  4. **总结经验写回去**：下次再去这个地方、或再和这位模特合作时，助手自动带上（例如"白鹭坡 17:40 后被楼挡""小鹿第一次放不开，先走动再拍"）。写回账户资料或地点经验前要我确认。

## 3. 机位面：白模与视角

- **真实楼块 + 影子 + 机位视角**：用地图数据里的真实建筑轮廓和高度把楼立起来；按当前时刻的太阳算出楼的影子；视角可以压到机位、朝拍摄方向、按焦段框出画面（人像竖 2:3、风光横 3:2，叠三分线）。时间可拖动，影子跟着走。树和小物件第一版不做；楼高数据缺的地方照实标出。
- **建筑遮挡计进见光时段**：山影之外再算楼影，时间线和机位卡上的"见光时段"更准。楼高数据不全或缺失时照实说"这一带楼高未知"，不默认为无遮挡。

## 4. 示意图（第一版演示里有、真实版缺的）

- **引导词配姿势小人**：助手给每句引导词选一个姿势类型（走、回头、靠、扶、插兜、拢围巾、迈步、站……固定一组），页面按类型画小人。不生成图片。
- **参数行**：焦段 · 光圈 · 快门 · ISO，只用我账户里有的器材。
- **构图示意框**：一个画幅框，标出人放哪、地平线在哪、三分线。
- **山影 / 楼影提示框**：橙色提示"此刻被山 / 楼挡住，几点开始见光"。

人流数据（没有真实来源）、生成样片、树木与小物件建模、驾车 / 公交路线（第一版已定不做）、交给其他工作台（等台间委托）。

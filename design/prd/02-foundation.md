## 2. 运行生命周期（grill 已完成）

### 2.1 目标与用户确认的交互原则

本项基于第 1 项统一后的主线实施，不混入正在进行的集成提交。DSH 负责后端和开发测试，Claude 负责前端契约、页面接线与真实验收；分支按 WORKFLOW 由用户开启，本 PRD 不提前指定。

统一的协作方式是：用户与 Agent 澄清目标 → Agent 形成计划（一句话或小报告均可）→ 用户同意 → Agent 在计划范围内自主实施 → 必要时询问 → 完成或提交问题/失败报告。

已确认的授权范围：

- 计划同意前允许沟通和必要的只读调查；不开始尚未授权的实施动作。
- 用户同意后，在计划范围内自主执行，不为已授权范围反复询问。
- 改变目标、明显扩大范围，或遇到必须由用户决定的动作时再询问。
- 计划批准不替代仍需单独批准的具体动作；看过报告不代表批准下一步。
- 给模型够用的工具和少量底线，不规定搜索顺序、次数、报告层数或失败后的操作步骤。计划内容与何时需要补充信息由 Agent 根据目标判断，程序负责维护授权与请求状态。
- 优先复用 DSH 原生计划、提问、会话记录和恢复机制；收件箱统一承接请求与报告。

本项先用已能工作的研究精读验证通用生命周期，不要求同时改完七台。课程最小插件留到第 3 项；QQ、微信、Muse 等外部渠道后续再接。

### 2.2 复用 DSH 的边界

设计时核对项目所用 `0.2.1-rc.4` 发布包：有 `plan-mode` / `exit_plan_mode`、`userQuestions.ask()` / `askTimed()`，以及持久问题和晚到回答的语义。`askTimed()` 返回 pending 只结束前台等待，问题仍可回答；后来的答案关联原问题进入新轮次，不伪造已结束工具调用的结果。

这些原生机制不等于 SDK 已具备全部 Web 端回答入口，也不等于返回 pending 后执行进程和写入占用已经释放。DSH 实施方按实际固定版本核实并复用，通过薄插件补足控制面接入；不因 SDK 接口缺失而另写完整会话引擎。未经本项验证，不把升级 DSH 当作默认要求。

计划模式本身不构成工具权限隔离。未确认的实施动作与单次审批由业务工具/插件执行前检查，不能只靠提示词。研究台现有下载审批保持单一决定来源，不重新增加原生与控制面双重审批。

### 2.3 任务、会话、执行段分开

- **任务**：用户希望完成的工作，例如读完一篇论文；跨多轮对话和多次等待持续存在。
- **会话**：该任务相关对话历史与原生恢复上下文；等待不会删除或清空它。
- **执行段**：实际占用 DSH 执行进程、工具和会话写入权的一段工作；可以因等待而正常结束，回答后再启动下一段。

具体表名、枚举和与现有 run 的映射由 DSH 在 spec 中给出，避免为这些概念复制多套相互独立的状态机。前端需要表达的业务状态如下：

| 状态 | 含义 | 执行资源 |
|---|---|---|
| 执行中 | 正在澄清、调查、形成计划或实施 | 按需占用 |
| 等待计划确认 | 已提交计划，等待同意或修改意见 | 没有其他独立工作时释放 |
| 等待回答 | 缺少信息或研究方向选择 | 没有其他独立工作时释放 |
| 等待批准 | 具体动作尚未获准 | 相关动作不执行，没有其他独立工作时释放 |
| 已完成 | 本项任务已完成并保存已有成果 | 释放 |
| 已停止 | 用户停止，或拒绝导致该任务结束 | 释放 |
| 出错停止 | 执行失败或中断，已有成果保留 | 自动收尾并释放，不留永久占用 |

任务可以有未回答的问题，同时执行不依赖该答案、且已获授权的工作。不因为某一条问题未答就强制结束所有工作；也不把请求工具返回 pending 当作允许执行依赖该答案的动作。

### 2.4 等待、回答与继续

1. 请求进入等待前，持久保存原问题/计划/动作、来源任务、所需回答方式和续接关联，保存已形成的结果。
2. 有独立工作可继续时交给 Agent 自行推进；确实要等人时，安全结束当前执行段，确认不再写会话后释放写入占用与不必要的进程。不能只删租约，让旧进程继续写入。
3. 等待请求保留在原工作台和收件箱中。不继续通过插件轮询占住整个执行段，也不维持一个必须永远存活的 Promise 才能回答。
4. 用户回答后，先持久保存响应，再按原生可用机制恢复对应会话，把原请求与答案关联送回。尚在原生等待调用内时走该调用的回答路径；原调用已结束时走关联的后续消息/轮次，不补造工具结果。
5. 计划确认绑定用户实际审阅的计划版本；动作批准绑定实际待执行动作。计划被修改时，不把旧批准自动用于扩大的范围。
6. 等待默认不因十分钟过去而过期、拒绝或自动批准。任务停止、请求被替代或动作已不适用时，关闭请求并说明原因；原生 timed 等待的截止只用于让出前台，不是业务请求失效时间。
7. 卡片或收件箱中的回答明确关联请求。普通聊天继续用于补充、纠正和改变目标，不机械地当作某个待答问题的答案。
8. 已处理请求在各入口同步，不重复续开同一工作，不残留待批卡。用户可以拒绝、修改或取消；不要求模型遵循固定措辞。

续上失败必须照实报告并保留问题、回答和已有记录；不能静默新建空会话，假装已经继承原任务。无需本轮建设新的长期记忆系统。

### 2.5 收件箱是统一入口

本项只做支持生命周期所必需的收件箱接线，不重做完整收件箱产品。

| 内容 | 可用操作与语义 |
|---|---|
| 计划确认 | 查看计划、同意、反馈修改或暂不执行 |
| 问题与决策 | 选择或自由回答，答案返回来源任务 |
| 单次动作审批 | 批准或拒绝具体动作；复用唯一审批记录 |
| 完成、问题与失败报告 | 查看结果、已完成部分、原因和后续选项；通知自身不占会话 |

原工作台与收件箱展示同一份请求的状态，不各维护一份批准记录。用户在创作台等其他页面处理研究台请求后，原任务能继续，不必切回研究页面；Agent 的完成或失败报告也能在收件箱查看。

最小语义包括：请求/报告标识、账户、来源工作台/档案/任务、类型、内容或内容引用、可用操作、状态、回答及关联。Claude 按这些语义确定前端契约，DSH 实现后端；不提前锁定字段名。

为后续渠道保留入口独立性：请求和报告不能只存在某个 React 组件或浏览器连接中，回答最终都进入相同的服务端处理路径。此次不集成外部消息平台、推送服务或 Muse；未来的汇报 Agent 默认无权代用户批准。

### 2.6 失败、取消与残留自动收尾

**正常等待不是残留。** 自动收尾只处理无有效执行者、执行失败/超时或已被停止但状态未落定的工作，不清空对话、论文和成果。

- 启动、模型请求、工具调用和进程停止都必须有有限的执行时限；等待人回答不计入这些时限。DSH 在 spec 中列出本地可配置的默认值与最长收尾时间，避免不同层叠加重试后变成无界等待。这里不指定模型的思考步骤或调查次数。
- 失败时记录可理解原因和已有成果，关闭失效待办，停止相关执行并释放占用。任务结束不等待用量补齐；未知费用保持未知，不冻结账户。
- 用户点击停止，相关请求关闭，系统停止该任务的实际执行；只有确认停止才报告已停止。暂未确认时显示正在收尾，后台继续有限的停止/核对流程，不能以永久 `cancel_unconfirmed` 加人工 SQL 作为正常恢复方案。
- 服务启动时核对未终结的工作，运行期间做轻量、周期性的状态核对。发现进程已退出而任务仍运行，自动补齐终态、清理占用与无效请求。
- 活跃执行的超时不能仅靠删除锁解决；先结束或确认原执行已失去写入能力，再让下一段工作取得会话。只处理相关任务，不重启整个账户来影响其他档案。
- 重启后有效等待请求仍可回答。被中断的执行先核对已保存结果与实际进程状态；无法确认完成时显示中断原因与重试入口，不静默重放付费或有副作用的动作。
- 客户端关闭页面、断网不等于取消后台任务。重新进入后读到真实状态，不因浏览器离线制造假失败。

收尾的用户结果是：任务有真实终态，或存在可理解、可回答的等待请求；用户能通过正常页面继续/重试，无需手工 SQL。服务器完全不可用时不承诺即时收尾，但恢复启动后必须自动处理。

### 2.7 验收：Claude 在真实页面亲自完成

| 编号 | 做什么 | 应该看到什么 |
|---|---|---|
| L1 | 与研究 Agent 沟通目标，收到计划后提出修改，再同意 | 计划可以简短；修改能讨论；同意前只做必要调查，同意后按已确认范围执行，不要求固定话术 |
| L2 | 任务提出问题或需要下载批准时，暂不处理，切到其他工作台 | 请求保留，不因离开页面或等待十分钟自动变成拒绝；无关档案仍可使用，等待不长期占执行进程/会话写入权（由后台状态辅助核对） |
| L3 | 留在其他工作台，从收件箱回答问题或批准动作 | 对应原任务续上，原卡与收件箱同步已处理；无需切回原页，不出现重复审批或重复动作 |
| L4 | 等待期间关闭页面、断开浏览器连接或重启栈，再进入 | 有效请求和上下文仍在，回答后能继续；登录持久化尚未实施，需要重新登录不算本项失败 |
| L5 | 正常执行中点击停止，或遇到一次可控的检索/模型失败；执行期间重启栈检查中断恢复 | 在 spec 公布的有限时间内自动收尾，页面有真实原因；后续任务或重试可用，不手工清 SQL、不伪造完成、不静默重复执行 |
| L6 | 一项精读完成或失败后查看收件箱 | 能看到报告、已有成果或失败原因及后续入口；报告不需要“批准”才能结束任务，费用未知也不阻塞 |

以上只验证核心用户流程，不扩展故障注入矩阵或边缘 case。Claude 可以在真实使用中顺着 Agent 的提问回答，选择适合的普通失败情形；不对模型做固定脚本或逐字断言。DSH 为确定性的状态转移和工具接线做开发测试，不替代 Claude 的页面验收。

### 2.8 实施边界与交付

优先改造现有研究提问、审批、会话占用和运行管理接线，复用 DSH 原生能力；去掉现有“插件阻塞轮询等人”“统一十分钟判过期”和需要人工释放残留的正常运行路径。仅当所选版本无法承接已定功能时，提出具体缺口与最小方案，不凭新版文档假定发布版已支持。

DSH 交付：实际复用的 DSH 能力与补足接口、执行时限和收尾配置、相关开发测试结果、Claude 的真实页面入口。Claude 负责请求卡、收件箱和状态呈现，契约双方协作。完成后按 WORKFLOW 验收合并；本项不自动获得新增真实模型额度。

本项不做：七台插件规范与课程插件、通用档案改造、持久登录、产物存储重建、模型分档、共享记忆、研究主助手、QQ/微信/Muse 集成或完整消息中心重设计。只保留未来按来源任务路由请求和报告的接口空间。

## 3. 工具与插件规范：隔离环境内基础工具全开

### 3.1 目标与顺序

用户新增要求：DSH 基础工具全部向 Agent 开放，包括 web_search、web_fetch、bash、grep、文件读写等；如何检索、下载和解析由 Agent 自行决定。不得以论文来源域名白名单、固定工具顺序或提示词教程限制其解决问题。

本项排在第 2 项之后，复用其等待、单次审批、取消、报告和收件箱能力。不在 `image: "host"` 的现有宿主执行环境中先打开 bash 再补隔离。可提前核实容器启动和依赖，正式切换按阶段顺序交付。

DSH 基础工具由内核提供，各实验室的插件增加专业能力，不复制一套基础工具实现。每个使用 DSH 的工作台一个专业插件；数据台完整使用 Data Formulator 的既定例外不变。本轮落地研究插件调整及一个课程台最小插件，不实现其余台完整业务。

### 3.2 隔离方案：每账户独立容器

选择每账户独立容器作为执行边界，DSH 在容器里运行，账户间不共享可写卷。复用现有容器基础中仍适用的部分，不恢复 OpenScience。DSH 沙箱可以作为容器内辅助约束，不以只设置 cwd 或提示词代替账户隔离。正式工具执行不回退到宿主模式。

| 区域 | Agent 权限 | 用途 |
|---|---|---|
| 当前档案工作区（容器内） | 读写、bash、grep、下载和解析 | 草稿、临时论文、解析文本、代码、安装在容器内的任务依赖 |
| 当前档案已批准材料快照 | 只读 | 读取已入档材料与版本；不能通过文件工具修改正式版本 |
| 正式记录数据库及权威产物目录 | 不直接挂载为可写，不提供数据库凭据 | 只能经控制面批准的业务提交操作写入 |
| 其他档案的私人工作目录 | 默认不暴露 | 确需访问时，经用户批准给出限定文件/目录访问；不授予整个账户文件卷 |
| 宿主 home、项目源码工作树、SSH/Provider 凭据、Docker socket、其他账户卷 | 不挂载、不提供权限 | 避免 bash 直接控制宿主或其他账户 |

同账户任务通过工作区权限或 DSH 实际沙箱约束限制到当前档案，不把“每账户一容器”误认为已实现档案间访问审批。访问其他目录获批后由受控工具提供限定能力或材料副本，不变成宿主任意 shell。

Provider 真实 key 继续只在控制面代理的宿主进程内读取和使用，不进入容器的文件、环境变量、argv、日志或模型上下文。容器调用模型代理使用限定身份凭据，它不是 Provider key。搜索等其他付费服务如需凭据，同样由代理注入；没有已配置服务时如实返回不可用，不隐藏工具来伪装支持。

### 3.3 网络与下载：公网来源自由，主机边界保留

- 不维护 arXiv、DOI、出版社、Unpaywall PDF 主机等来源域名白名单；公网来源和正常跳转不因域名不在名单内被拒绝。
- web_fetch、bash 下载、专业论文工具遵守同一执行环境边界，不能一个工具开放而另一个工具继续报来源名单拒绝。专业论文工具尽可能在隔离环境内处理网络与解析，或通过等效隔离的下载服务执行。
- 容器可访问公网。宿主、局域网管理服务、其他账户网络和基础设施元数据仍不属于公网资源；网络隔离在环境层落实，包含跳转后的目标，不依靠模型自觉遵守。模型代理及必要业务 API 是明确提供的受认证内部入口，不能借代理任意转发到内网。
- 这不是论文来源白名单：公共 DOI/OA PDF 应可访问；来源本身的登录、付费、限流、下线或网络错误仍可能导致下载失败，要将真实错误交给 Agent，不承诺所有 PDF 都能下载。
- 移除当前造成公网 OA 来源 `PAPERS_EGRESS_DENIED` 的名单条件，不删除环境隔离。不得要求用户改说“用 arXiv”，不硬编码模型失败后改用哪条路线。

### 3.4 基础工具开放与两条写入底线

所有基础工具在隔离环境中可用，包括计划澄清时必要的查找、下载和解析。用户已同意的计划内，Agent 可自主使用这些工具；不再用澄清阶段隐藏下载工具来约束其方法。第 2 项的计划授权和必要询问边界仍然有效。

区分两种“写入”：

1. **工作草稿与计算中间文件**：当前档案工作区里的下载、解压、转换、笔记草稿、脚本和临时输出，可自主读写，不每次弹审批。
2. **正式入档或修改档案外对象**：将论文、讲解、发现、课程计划等提交成正式记录，或操作当前档案之外的文件/对象，要用户批准一次。请求展示拟写入内容或可审阅差异和目标，批准只覆盖本次内容与范围。

同一个提交可以包含一组相关成果，例如一份讲解及其发现卡，不必每张卡都问一次。临时区中出现文件不代表已正式入档。正式提交只能通过受控业务工具完成，不能提供可让 bash 绕过审批的数据库或权威文件写权限。已经批准的同一提交重试不重复写入、不再次索要同一批准；内容或范围变化需重新确认。

本项上线后，旧 B1 的“下载一次审批”保留为历史验收记录，不再要求每个下载动作弹卡：自主下载到工作区，正式采用/入档时审批。不得既套旧下载审批又增加同一成果的重复入档审批。该体验变化由 Claude 同步页面和契约。

只保留少数行为底线：计划及需用户决定的范围遵守第 2 项；正式入档和档案外动作需批准；不编造论文、作者、页码或执行结果。缺原文页码时照实说明，不强迫模型按固定步骤处理。

### 3.5 插件最小规范

| 部分 | 统一约定 |
|---|---|
| 基础工具 | 从 DSH 复用，不被专业插件的能力名单整体遮蔽；可执行范围由环境约束 |
| 专业工具 | 声明工具用途、输入输出、读/草稿写/正式提交/档案外动作分类；不携带固定解题步骤 |
| 请求与审批 | 使用第 2 项统一请求，同一份状态在原工作台与收件箱展示，支持等待后恢复 |
| 业务范围 | 使用可信会话绑定的账户和档案，不由模型提供的账户参数决定权限 |
| 错误 | 至少提供稳定 code 与可理解 message，必要时附真实服务错误；失败不伪装为空结果或成功，不要求模型固定重试次数/换源步骤 |
| 成果 | 草稿和正式记录明确区分；正式记录通过批准后的提交工具保存，沿用现有存储，不重建产物平台 |
| 提示词/技能 | 专业目标、工具说明和少数底线；不写搜索顺序、下载教程、次数配额或“规则 N” |

共用网络、文件、请求和提交能力集中复用，专业插件只管理本台语义。实现文件位置由 DSH 按统一主线的现有目录确定，不借此进行大规模拆包。

### 3.6 用课程台最小插件验证

用户提出一个学习目标 → Agent 自行沟通和必要调查 → 提交一份简短学习计划 → 用户可在收件箱同意或提出修改 → 同意后写入一份正式课程计划，显示在课程档案中，并发完成报告。

这份计划可以同时作为待确认计划和待入档内容：同一次明确批准可以覆盖用户看见的计划及其入档，不增加重复卡片。使用现有档案能力所需的最小接线，不提前实现第 4 项七台 Files；若需专门进入该课程样本的临时入口，由 Claude 提供真实页面入口，不另造通用档案模型。

本轮不做完整备课链、课堂生成、考核、学习 map 或研究委托。检索与工具选择交给 Agent，不要求演示固定调用轨迹。

### 3.7 验收：Claude 亲自使用真实页面

| 编号 | 做什么 | 应该看到什么 |
|---|---|---|
| T1 | 在研究台提出普通论文需求，必要时提供一个可公开访问的 DOI/OA PDF 链接 | Agent 自己决定查找、下载与解析；不因来源未列入名单被拒，不要求用户指定 arXiv；来源确实不可用时照实说明 |
| T2 | 在页面任务中使用基础工具处理下载的材料 | web、bash、grep、读写文件可用，执行在账户容器及当前档案工作区；不落到宿主任意目录（由运行信息辅助核对） |
| T3 | 生成草稿后正式入档，分别体验一次批准与拒绝 | 草稿不逐次打扰；正式写入前能审阅，批准后生效，拒绝不写正式记录；页面和收件箱状态一致 |
| T4 | 提出一次需要使用档案外指定文件的正常任务 | 明确说明对象和操作范围，经一次批准后受控执行；不自动取得整个宿主权限 |
| T5 | 在课程台最小插件提出学习目标，讨论计划并确认 | 使用共同工具和生命周期完成计划入档，收件箱可处理请求及查看报告；无固定模型话术要求 |

DSH 验证账户容器、目录范围与 key 不进入环境的配置和开发行为，Claude 看真实页面效果及必要运行信息。不增加攻击测试矩阵、凭据扫描工程或固定模型验收脚本。

### 3.8 与后续工作的边界

本项不把产物存储、模型分档、共享记忆、七台完整功能纳入实施。记录以可关联档案、版本和任务的现有接口保存；模型接入继续代理，不把专业插件写死到某个模型；未来共享记忆通过明确工具接入，不默认共享其他档案目录。

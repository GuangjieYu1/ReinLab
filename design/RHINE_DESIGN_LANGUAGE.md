## 1. 六条原则

1. **一切皆档案。** 工作区是档案（`X—013`），会话、需求、镜头、用例都是档案里的文件。
2. **单色为底，一色为信号。** 页面由纸白、灰阶和墨黑构成；莱茵橙只表示「看这里」：当前焦点、AI 动过的东西、需要你决定的事。一屏里橙色超过三处就是用错了。
3. **尺度反差。** 超大字（档案号、幽灵大字、时钟）与 11px 等宽微标注同屏出现，中间层级尽量少。这是莱茵感的主要来源。
4. **一切有标注。** 重要对象旁有引线和编号标签，说明它是什么、属于哪一节。标注对齐网格，不乱飞。
5. **一切可追溯。** AI 做的每件事都留下一条记录，能定位、能回放、能撤回。
6. **克制的动。** 两种标志动效（§6）+ 少量辅助动效，全部尊重「减少动态效果」。

### 2.4 数据可视化色板

单色优先：默认系列用墨，对比系列用灰阶，被选中 / 被 AI 标记的系列用橙。

`#141213` 墨 · `#6b6865` 灰 · `#9a9792` 浅灰 · `#ff7a1a` 橙（仅高亮）· `#3a3837` 深灰 · `#c9c6c0` 线灰

- 比较类图表纵轴按数据范围自适应，除非 0 有业务意义。
- 需要多于 4 个类别时，用纹理（斜线、点阵）区分，而不是加颜色。

### 2.5 字体

| 角色 | 字体 | 用途 |
|---|---|---|
| 展示 | `Archivo`（宽体 112–125，字重 700–800）+ `Noto Sans SC` 粗体 | 档案号、幽灵大字、区块名 `CMPT CTRL`、大时钟 |
| UI | `DM Sans`, `Noto Sans SC` | 所有界面文字 |
| 等宽 | `IBM Plex Mono` | 微标注、编号、分支、时间、计数、代码 |
| 长文 | `Noto Serif SC` | 需求文档正文、小说正文、报告 |

字号阶梯（px）：`11` 微标注 · `12` 密集 UI · `13` 默认正文 · `14` 强调正文 · `16` 面板标题 · `22` 区块标题 · `40` 档案号 / 时钟 · `120+` 幽灵大字

- **微标注**：11px 等宽、`letter-spacing: .12em`、大写、`--rh-ink-4`。如 `SECTION 001 · TERMINAL NODE`。
- **区块名**：展示字体宽体大写，常放在黑块里反白。
- 长文阅读区行宽 64–72 字符，行高 1.8。

### 2.6 间距、圆角、边框、阴影

- 4px 网格：`4 8 12 16 24 32 48 64`。
- **圆角一律 0。** 只有信号灯和头像是圆形。
- 边框 1px `--rh-line`；选中 1px `--rh-ink`；焦点 / AI 1px `--rh-accent`。
- 阴影只给浮层：`0 12px 32px rgba(20,18,19,.14)`。面板之间靠缝和线分隔。
- 可选：极淡的颗粒噪点叠层（`opacity .04`），开启「减少动态效果」或低性能模式时关闭。

### 2.7 动效参数

| Token | 值 |
|---|---|
| `--rh-dur-1` | 120ms 悬停、按下 |
| `--rh-dur-2` | 200ms 展开、切换 |
| `--rh-dur-3` | 320ms 光圈对焦 |
| `--rh-dur-4` | 600ms 橙框闪烁 |
| `--rh-ease` | `cubic-bezier(.2,.7,.2,1)` |

### 3.1 工作台骨架

```
┌ 顶栏：∞± RHINE LAB · 01 CURR 02 RSCH 03 ENGR … · 档案号 X—013 · 档案名 · 时间 ─────────┐
├ 面签（可选）：01 · 需求  02 · 开发  03 · 测试  04 · 本体   …… 分支 · ⌘K           ┤
│ ┌ 01 ┐┌ 02 ┐┌ 03 ┐┌ 04 Agent ┐                                                    │
│ │    ││    ││    ││          │   编号面板 2–5 个，面板缝 8px                        │
│ └────┘└────┘└────┘└──────────┘                                                    │
└ 状态条：■ 环境 · 分支 · 检查点 · 计数 · 示例数据                     POWERED BY RHINE LAB ┘
```

- 台签、面签都写成 `01 · 名称` 的编号页签，当前项反白（黑底白字）。
- 面板头 = 编号黑块（白字）+ 标题 + 等宽英文微标注 + 操作 + 最右 ⤢。
- 网格：12 列，列宽随视口；所有引线标注的标签框贴齐网格。

### 3.2 响应式

- ≥ 1280：完整多栏。
- 900–1279：Agent 坞收为右侧抽屉。
- < 900：面板按编号竖排；Agent 坞变底部上拉面板；面签横向滚动。页面不出现横向滚动；幽灵大字和引线标注在窄屏隐藏。

## 4. 视觉词汇

这是「看起来像莱茵生命」的部分。每个工作台至少使用其中三种，但同一个区域不叠加超过两种。

| 名称 | 做法 | 用在哪里 |
|---|---|---|
| **幽灵大字** | 120px+ 展示字，`--rh-ghost` 色或 1px 描边，压在内容背后，部分被面板遮住 | 面的入口、空状态、档案查看器背景（如 `REQ`、`TEST`、`WORLD`） |
| **引线标注** | 1px 细线从对象斜出 → 折成水平 → 小标签框（上：等宽编号，下：中文名） | 关键对象说明、首次引导、Archify / 本体图上的选中节点 |
| **黑块** | 墨色实心方块，内含反白区块名 + 小字说明 + 右上一个白色小圆点 | 区块身份卡、面板编号、锁定 / 封存状态 |
| **反白标签** | 文字放进墨色或描边方框，等宽或展示字 | 当前标题、档案名、选中项 |
| **橙色方块** | `■` 6–8px 橙色实心方块，作为前缀 | 「这里需要你」的条目、当前步骤、警示文字前缀 |
| **编号页签** | `01 · ARCHIVE`，当前页反白 | 台签、面签、二级导航 |
| **标本盒** | 档案以带厚度的盒子 / 卡片呈现（CSS 透视 + 侧面），可从阵列中抽出 | 档案柜（选择工作区）、文件列表的大图模式 |
| **微标注带** | 一行等宽小字串：`PCM 32/48 · 25 TRACKS · 1:20:04` | 面板头下方、卡片底部、状态条 |
| **信号灯** | 6px 圆点，信号绿 = 在线 / 通过，橙 = 待处理，灰 = 离线 | 状态 |

## 6. 标志动效

### 6.1 光圈对焦 · Aperture —「看这里」

一圈橙色描边从 140% 收缩到 100%，透明度 0 → 1 → 0.6，320ms，最后保留 1px 橙色描边。
用于：跨面板联动、时间条跳转、Agent 在回复中引用某对象、搜索定位。

### 6.2 莫比乌斯 · Möbius —「循环正在运行」

莱茵生命标志本身就是 ∞±，所以这是品牌母题。一条 ∞ 路径（左环 `+`、右环 `−`），橙色线段沿路径流动（`stroke-dashoffset`，周期 2.4s）；路径上的节点代表循环阶段，当前节点为实心。
用于：研究循环、TDD / 批量测试、生成队列、自动化运行。
空闲时 ∞ 静止为墨色线稿，即品牌标志。

### 6.3 辅助动效

| 动效 | 含义 | 规格 |
|---|---|---|
| 橙框闪烁 | 改动刚刚落地 | 1px 橙框 600ms 淡出 |
| 流动虚线框 | AI 正在处理这个对象 | 1px 橙色虚线，`dashoffset` 循环 1.2s |
| 扫描转场 | 切换面 / 打开档案 | 一条 1px 横线自上而下扫过，内容随之出现，240ms |
| 解密 | 档案打开时标题字符快速替换后定格 | 300ms，仅档案号与标题 |
| 逐条出现 | 新事件进入事件流 | 位移 4px + 透明度，200ms |

「减少动态效果」开启时：光圈对焦变静态橙框，莫比乌斯停止流动只保留当前节点，扫描与解密直接到终态，颗粒关闭。

## 7. Agent 坞 · 所有工作台共用

**每个档案都有一个常驻 Agent，它是这个工作区的操作员。**

### 7.1 结构（自上而下）

1. **头部**：黑块 `AGENT` + 名称 + 维护对象（如 `ISS-34 · feat/ISS-34-keyboard-nav`）+ 信号灯
2. **计划**：TodoRail，钉在顶部，可折叠
3. **建议动作**：2–4 个描边方框按钮，随上下文变化（`ToSpec`、`ToTDD`、`跑测试`）
4. **对话流**：消息、工具调用（折叠为一行）、审批卡
5. **输入框**：`@` 引用对象，`/` 调用动作；下方一行微标注写权限模式

### 7.2 动作表：按钮与 Agent 共用

```ts
type RhineAction = {
  id: string;                 // 'run_tests'
  label: string;              // '运行测试'
  bench: BenchId;
  risk: 'read' | 'write' | 'danger';
  params?: Schema;
  run(ctx, params): AsyncIterable<RhineEvent>;  // 现阶段为前端模拟
};
```

| 风险 | 行为 |
|---|---|
| `read` | 直接执行 |
| `write` | 弹审批卡 |
| `danger` | Agent 不能执行，只提示你自己点 |

你说「跑一下测试」和点「运行测试」按钮，界面反应完全一样；Agent 操作中的对象显示流动虚线框，完成后橙框闪烁。每个档案的第一个文件是**工作区说明**，Agent 行动前都会读它。

**例外**：数据工作台沿用 Data Formulator 的内联对话，不额外放 Agent 坞。

## 9. 文案

- 中文为主，等宽英文只做微标注与区块名（`CMPT CTRL`、`TERMINAL NODE`），不翻译正文。
- 按钮动词开头：「提交 MR」「运行测试」「生成候选」。
- 状态短词：「已就绪」「运行中」「待审批」「已驳回」「冲突 2」。
- 空状态是邀请：「把一份需求拖进来，或者让助手起草」。
- 示例数据必须在状态条注明「示例数据 · 不连接模型」。

## 10. 性能约束

- **不使用 WebGL。** 需要三维感的地方：
  - 标本盒、档案阵列：CSS `perspective` + `transform`
  - 白模视口：Canvas 2D 软渲染（自写投影 + 画家算法，低多边形）
- 动画只动 `transform` 和 `opacity`。
- 颗粒、扫描等装饰效果在低性能模式下关闭。

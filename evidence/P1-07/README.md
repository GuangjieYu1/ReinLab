# P1-07 · 预估、层级预算与费用门禁

真实Postgres保存估算、层级划拨、工具费用保留与结算。三个新增表FORCE RLS，复合外键绑定账户/档案/运行/月份；估算应用只读只追加。六位人民币用BigInt计算，run及委托累计金额与账本统一精度，额度/GPU累计用bigint防止整型溢出。账户只计根划拨，档案视图只计本档案收到的最上层划拨，父/子/跨档案委托不会重复预留或重复算费用。

工具先原子保留最大费用、会员次数与GPU秒，结束后结算真实回报。80%只提醒，100%暂停并生成预算审批；实际超出保留额仍记真实费用及超额原因，暂停后续。未知API费用保持null且暂停待对账，会员/GPU按独立量结算，不伪造人民币费用。追加预算需用户请求，可分别追加人民币/额度/GPU。新月先停；旧用量结清、上级当月预算确认后，用户显式确认新月预算，同一运行保留历史累计费用继续。

预估生产路径只从`https://models.dev/api.json`读取公开真实目录，限制大小/超时并缓存5分钟；未知路由、缺汇率、未知或双零价格均503。每份估算保存模型、目录原始SHA256、显式汇率、token假设，10分钟有效；模式/角色模型档/档案绑定，不可重复消费。确认后只创建真实queued记录，输入持久化前脱敏；P1-10前不提交模型，不宣称执行完成。

token规划假设：每轮每份输入10000、输出3000；精读1轮、群研4轮（默认8份）、自研16轮，价格乘2安全系数。它是可审阅的估算政策，不是实际用量；默认预算精读5元、群研30元、自研由用户指定。会员次数与GPU预估尚无计划输入，明确返回null；实际结算只取回报，不拿规划量补实际。

独立评审发现并要求补齐的三维层级现已实现：run与委托的会员/GPU上限约束子授予，父直接在途量和子未用额度均从父剩余扣除。计数向祖先累计，父100%或未知费用也暂停；子不能绕过上级暂停。用户明确追加后重新核准合格祖先，再继续原运行。根档案没有给定账户会员/GPU月上限时保持null，已有run/委托上限仍为明确的0或有限值。Q026/027详述边界。

应用只能更新预算计数/决定字段，不能改写来源、月份、收据身份或原始工具上限。数据库触发器拒绝来源环及超过32层；单次费用保留event字段上限，可信累计支持numeric(18,6)，两笔合法大额回报不会因总额超过单笔范围丢账。父测试34项，独立原创28项，独立复跑共62/62；第三轮评审通过R1/R2均关闭。最终全仓563/563通过且退出0；类型、边界检查和mock构建通过，250个前端基线哈希一致。行覆盖246/253（97.23%，覆盖采集时为34+14样本）。
